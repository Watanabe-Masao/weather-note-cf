# research/

アプリの外で行う分析です。アプリの動きには影響しません。

## compare_models.py

設定 ＞ 最近との差 β ＞［CSVを書き出す］の CSV を読み、「最近の気温（履歴）が感じ方にどう効くか」の関数の形を比べます。

- M0：その場の肌感（日なた／日かげ）だけ
- M1：M0 ＋ g(気温 − 最近の基準)。g は 線形・対数・べき乗・非対称対数
- 最近の基準は、記録ごとの `history_60d` から α の候補ごとに計算し直す（アプリと同じ規則）
- 早い 70% で当てはめ、遅い 30% で確かめる（RMSE・MAE）。BIC も出す。`--ordinal` で順序ロジットの対数損失も

```sh
python3 research/compare_models.py weather-note-reports-2026-12-01.csv --ordinal
python3 research/compare_models.py --simulate 200      # 作り物の記録で試す
```

numpy と scipy だけを使います。

### α の向き

アプリと CSV の `baseline_alpha` は規格（EN 16798-1）の向き（前の基準の重み、標準 0.8）です。研究メモの「更新率」（前日の重み）は `update_rate` ＝ 1 − α の列、両方で同じ意味になる半減期は `half_life_days` の列にあります。

### アプリへの反映

アプリの中のモデル（`src/beta/comfort.ts`：快適の中心と範囲が動く順序モデル）は、要因を少なく絞っています。ここで別の要因や形が、新しい期間でもはっきり効き続けたときに、モデルの要因に加えるかを決めます。CSV の `comfort_*`・`p_*` 列には、送信時にアプリが出した中心・範囲・確率が入っています。

## bayes_index.py

前日・直近1週間の湿度・日照（日射）・雨・天気、申告の風と空が感じ方にどう効くかを、ベイズ線形回帰（正規・逆ガンマの共役事前分布、事前の広さは周辺尤度で選ぶ）で推定し、指数を作ります。

- 各要因の効き方を、95% 信用区間つきで出す（区間が 0 をまたぐ要因は「まだデータで示せていない」）
- 早い 70% で当てはめ、遅い 30% で確かめる（その場の温度だけのモデルと比べる）。周辺尤度でも比べる
- 指数 ＝ 事後平均による予測。要因のまとまり（その場／最近の気温／前日／直近1週間／風／空）ごとの寄与に分けて出す
- `--out index.json` で係数を書き出す（将来アプリに入れる候補。研究用）
- `--sky` で予報の天気と見た空の突き合わせ表（予報の検証は別の分析として扱う）

```sh
python3 research/bayes_index.py weather-note-reports.csv --out index.json
python3 research/bayes_index.py weather-note-reports.csv --sky
python3 research/bayes_index.py --simulate 240        # 前日の湿度と週の日照が効く作り物の記録で試す
```

要因が多いので、40件以上・数週間分の記録がそろってから使います。
