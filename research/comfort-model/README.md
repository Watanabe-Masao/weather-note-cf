## 合成データによる検証（#35）の結論

答えが分かっている仮想の人を使いました。条件は次のとおりです。

- ちょうどよい温度：基準15℃のとき 20℃。基準1℃につき 0.33℃動く
- 範囲の半分 3℃、外の1段 4℃、ぼやけ 0.7℃
- 高知に似た季節の気温の中で、1日1〜3回答える

この人で、モデルが入れたものを取り戻せるか、取り戻せないときにそう言えるかを確かめました。

### 1. 回復と区間（A）
- ちょうどよい温度 μ の誤差の平均：10件で 0.5℃、40件で 0.36℃、160件で 0.17℃。件数とともに小さくなります。
- 95%区間が真の値を含む割合は、μ・慣れの傾き・h・s のどれも 91〜100% でした。区間は正直です。
- ラプラス近似の区間は、もっと正確な方法（重点サンプリング）より、少ない件数で平均 8% 狭いだけでした（比 0.92〜0.96）。近似は使えます。補正は入れていません。

### 2. 学習の段階の境目（B）
- μ の95%区間の幅が 4℃ 以内なら、μ の誤差はどの回も 2℃ 以内でした（平均 0.3〜0.54℃）。
- 区間が 4〜7℃ でも、誤差はほぼ 2℃ 以内でした。ただし、これは「モデルの形が正しい」理想的な場合です。実データでは観測と体感のずれが加わるため、**境目の 4℃ は保守的なまま残します。**
- この理想的な人では、検証可能（区間 4℃ 以内）に届くのは、およそ 15〜20件でした。
- 予測の成績（RPS）は、5件の時点で、その人の過去の答えの割合（基準）を大きく上回りました（0.035 対 0.128。真の確率は 0.024）。気温の幅が広いと、答えの割合だけでは当てられないためです。

### 3. 推定できないと言えるか（C）

| 条件 | 結果 |
| --- | --- |
| 寒い側の答えしかない | 10回とも「情報不足」 |
| 温度がとても狭い（2℃の幅） | 10回とも「情報不足」 |
| 1日に集中 | 10回とも「情報不足」 |
| 答えが少ない（6件） | 「情報不足」か「暫定」。「検証可能」にはならない |
| 入力の3割が欠けている | 落ちずに推定し、欠けたモデルは使える記録だけで学習する |
| 2つの入力が一緒に動く（相関 0.97） | 10回とも「分けられない」と検出（推定の相関 −0.94）。根拠の画面に表示するようにした |
| 本人が途中で変わる（中心 +3℃） | 変化の後の事前予測が、平均 −0.69段ずれる。直近10件の平均が −0.5段を下回る判定で、10回とも検出し、変わらない人では誤検出 0/10。**この判定を #34 の成績の画面に入れる** |

### 4. モデルの形に合わない人（D）
寒い側の段が狭く（2.5℃）、暑い側が広い（5.5℃）人では、次のようになりました。

- 学習の段階や基準との比較では、ふつうに使えます。
- ただし μ の誤差は件数を増やしても 0.5℃前後から減らず、RPS も真の確率との差（0.029 対 0.023）が残ります。形の違いによる偏りです。
- 「左右で段の幅が違う」モデルは、#37 の候補にします。採否は、事前予測の成績が良くなるかどうかで決めます。

### 境目の決定（暫定から、根拠のある値へ）

| 境目 | 値 | 根拠 |
| --- | --- | --- |
| 温度の幅 | 5℃ | 2℃の幅では情報不足と判定できた。5℃は、範囲の半分（約3℃）の両側に届く幅 |
| 記録した日 | 3日 | 1日に集中した40件を情報不足にできた |
| μ の区間 | 4℃ | 区間4℃以内で、誤差はいつも2℃以内。理想的な場合の結果なので緩めない |
| 検証用の予測 | 20件 | 基準に勝つかどうかの判断に使う件数。変えない |
| 観測の古さ | 120分 | 合成データでは確かめられない（実データで見直す） |
| 慣れの速さ α を選ぶ件数 | 30件 | この検証の対象外。実データで見直す |

### この検証で分からないこと
- 実際の人の答えは、モデルの形どおりではありません（D で一部を確かめた）。
- 観測所の値と、その場の体感のずれ（日なた・日かげ・風）は、合成データでは再現していません。
- 境目は、実データがたまったら同じスクリプトの考え方で見直します。
