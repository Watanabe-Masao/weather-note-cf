# 計算の決まり（新しい仕組み `src/core/`）

肌感・慣れ・判定などの計算を、白紙から組み直すための決まり。いまの式と数字は参考にするだけで、守る対象ではない。新しい仕組みは `src/core/` に作り、できた所から画面をつなぎ替える。いまの計算（`shared/`・`src/beta/`）は、つなぎ替えが済んだ所から消す。

2026-11-15 決定。

## 0. まず二つに分ける：学習なし版と学習あり版

| 版 | 使うもの | 置き場所 | 役目 |
|---|---|---|---|
| **学習なし版** | 材料・推測値・設定だけ。**答え（人の記録）を読まない** | `src/core/plain/` | 記録が1件もなくても答えを出す。学習あり版を比べる物差し |
| **学習あり版** | 学習なし版と同じ材料・推測値に、答えから合わせた数を足す | `src/core/learned/` | その人に合わせる。学習なし版より当たるときだけ使う |

- 材料と推測値は、両方の版で**同じもの**を使う（`src/core/material/`・`src/core/estimate/`）。版ごとに作り直さない
- 学習なし版は、学習あり版と答えを読み込まない（矢印は 学習あり → 学習なし の一方向だけ）。テストで確かめる
- 学習あり版の成績は、いつも学習なし版と並べて出す。勝てない間は学習なし版を出す

## 1. 層は4つ、矢印は一方向

```
材料（material） → 推測値（estimate） → 判定（plain／learned） → 画面（ui）
```

| 層 | 持つもの | してはいけないこと |
|---|---|---|
| 材料 | 記録と予報を**同じ形**にそろえた値。どこから来たか（記録・予報、提供元、速報か）を一緒に持つ | 計算・補い・丸め |
| 推測値 | 材料（とほかの推測値）から計算する値。1つの値に1つのモジュール | データの取得、画面の都合 |
| 判定 | 推測値の名前を並べて作る組み合わせ（7段の確率など） | 推測値を自分で計算し直す |
| 画面 | 判定と推測値を見せる | 計算 |

- `src/core/` の中のファイルは、`src/core/` の外を import しない（例外は `shared/types.ts` の型だけ）。テストで確かめる（`test/data/core-boundary.test.ts`）
- 取得（保存データ・API）は `src/core/` の外。core の関数は、材料を引数で受け取る純粋な関数にする。同じ入力なら必ず同じ答え

## 2. データがないものは扱わない

- 材料の値は「ある（数）」か「ない（null）」の2つだけ。**代わりの値で埋めない**（0℃、予報で穴埋め、日の値で時間の値の代わり、などはしない）
- 入力が1つでも「ない」なら、その推測値も「ない」。画面は「—」を出す
- 代わりの材料を使いたいときは、それを**別の推測値として名前を付けて**作る（例：「日照から推測した日射」）。黙って差し替えない

## 3. 材料にするのは、記録と予報の両方にあるものだけ

| 材料 | 毎時 | 日 | 単位 |
|---|---|---|---|
| 気温 | ○ | ○（平均・最高・最低） | ℃ |
| 湿度 | ○ | ○（平均） | % |
| 風速 | ○ | ○（平均・最大） | m/s |
| 最大瞬間風速 | — | ○ | m/s |
| 降水量 | ○ | ○ | mm |
| 日照時間 | ○ | ○ | 時間 |
| 気圧（海面） | ○ | ○ | hPa |

材料にしないもの（理由）：
- 日射：記録は測っている地点だけ → 日照などからの**推測値**にする
- 露点：予報にない → 気温と湿度からの推測値にする
- 天気の文字・天気コード：記録と予報で形が違う → 表示だけ
- 降水確率：記録にない → 表示だけ
- 毎時の最大瞬間風速：記録（毎時の表）にない

## 4. 品質の扱い

気象庁の品質記号で、材料に入れるかを決める。

| 気象庁 | 材料 |
|---|---|
| 正常値 | 入れる |
| 準正常値（`)`） | 入れる。`rough` に名前を残す |
| 資料不足値（`]`） | 入れない（null） |
| 現象なし（`--`、降水・日照） | 0 として入れる（測って 0 だった） |
| 欠測・未発表・夜の日照の空欄 | 入れない（null） |

夜の日照は「測っていない」なので null のまま。「夜は日照 0」とするのは、太陽の高さを使う推測値の役目。

## 5. 推測値のモジュールの形（次の段で作る）

```ts
defineEstimate({
  id: "feel.shade",          // 名前。課題・研究メモでもこの名前で呼ぶ
  version: 1,                // 式を変えたら上げる
  needs: ["temp", "humidity", "wind"],  // 材料か、ほかの推測値の id
  compute: (x) => ...,       // needs が全部そろったときだけ呼ばれる。そろわなければ null
});
```

- 依存は `needs` だけ。関数の中でほかの値を取りに行かない
- 同じ値の候補（慣れの式が3つ、など）は、別の id にする（`adapt.long.mean30`、`adapt.long.ema` など）。どれを使うかは判定の側で選ぶ
- 係数は、そのモジュールの中に1か所だけ。ほかで同じ数を書かない
- 依存の図は、コードから作る（手で書かない）

## 6. 記録（答え）に保存するもの

- 保存するのは**材料と答えだけ**。肌感・基準・差などの推測値は保存しない
- 推測値は、いつでもいまの式で計算し直す。式を変えたら、全部の記録が新しい式で読み直される
- これまでの記録は、材料と答えだけを引き継ぐ。足りない材料は気象庁の記録から取り直す

## 7. 組み替えと比べ方

- 判定は「どの推測値を、どう組み合わせるか」の宣言にする。学習なし版と学習あり版の両方にある
- 学習なし版の判定の数（境目など）は設定か、根拠を書いた定数。答えから合わせた数は学習あり版にだけ置く
- 比べるときは、同じ材料と同じ答えに、別の組み合わせを流すだけ。成績の決まりは #117
- 判定を採用する・版を上げるのは承認してから（D10）

## 8. 設計の原則との対応

| 原則 | この仕組みでの形 |
|---|---|
| SRP（単一責任） | 1つの推測値に1つのモジュール（5） |
| OCP（開放閉鎖） | 新しい式は新しい id で足す。使っている式は書き換えない（変えるなら version を上げる） |
| LSP（置換可能性） | 同じ値の候補は同じ入出力の形にして、判定の側で差し替えられるようにする |
| ISP（インターフェース分離） | 学習なし版と学習あり版、計算と表示で、必要な形を分ける（0・1） |
| DIP（依存性逆転） | core はデータの取り方も画面も知らない。材料は引数で受け取る（1、テストで確認） |
| DRY | 係数・単位・依存の正本は推測値のモジュールの中だけ。別の登録表や手書きの地図を正本にしない。図はコードから作る |
| KISS | 汎用の実行エンジンは作らない。`needs` がそろえば計算するだけ |

## 9. ライブラリ

増やすのは、決まりを確かめるのに手で書くより確かなときだけ。

| ライブラリ | 使う所 | 入れる時 |
|---|---|---|
| fast-check | 推測値と判定の性質を、多数の入力で確かめる（入力がなければ答えもない、範囲、確率の合計が1、学習なし版は答えを変えても結果が同じ） | 推測値の段 |
| Zod | 外から来るものの入口だけ（保存されている答えの記録、D1 から戻るデータ）。core の中は TypeScript の型で足りる | 古い記録を引き継ぐ段 |
| Mermaid | 依存の図を `needs` から作って文書に出す（いまの文書と同じ） | 推測値の段 |

入れないもの：Madge（core の境目は 1 のテストで確かめている）、React Flow・ELK.js（画面でモデルを探す必要が出るまで）。
