### A-2. 配信のされ方

| 一覧 | 載る範囲（実測） | 警報まわり |
|---|---|---|
| extra.xml（随時・高頻度） | 約10時間分（212件） | VPWW53/54/55〜61、竜巻、気象情報 |
| extra_l.xml（随時・長期） | 約168時間＝7日分（3497件） | 同上 |
| regular.xml（定時・高頻度） | 約10時間分 | VPWP50、VPWS50、VPFD60/61、VPFW60 |
| regular_l.xml（定時・長期） | 約168時間＝7日分（9264件、4.4MB） | 同上 |
| other / other_l | 約9時間／7日 | 海上警報など。高知の警報は無し |

- 警報・注意報（VPWW53/54、VPWW55〜61）は **随時（extra）**、時系列（VPWP50）・集約（VPWS50）・早期注意（VPFD60/61、VPFW60）は **定時（regular）** に載ります。
- 公式の説明：随時の長期フィードは「毎時更新し、数日間の全入電を掲載」、高頻度は「毎分更新し、直近少なくとも10分入電」（e-Gov データポータルの登録）。実測では高頻度でも約10時間分が載っていました。
- 取りこぼしたとき：長期の一覧に載っている7日以内なら、電文は取れます（7日前の電文も HTTP 200 で読めた）。**一覧から外れたあとも電文の URL が生きているかは確かめられませんでした**（古いファイル名が手元に無かったため）。気象庁の電文の置き場の一覧（/developer/xml/data/）は 404 で、過去の電文をまとめて出す仕組みは見つかりませんでした。
- 予報の取り込み（forecastArchive.ts）と同じく「一覧から外れたら取れない」と見て扱うのが安全です（推測）。

### A-4. 中身の形

**区域の細かさ**（VPWW53・54、Ｒ０６ とも同じ4段階）：
- 府県予報区等：高知県（390000）1つ
- 一次細分区域等：3つ（高知市は 中部 390010）
- 市町村等をまとめた地域等：7つ
- 市町村等：34（高知市 3920100）
- VPWP50 は市町村等ごと（高知市の項目あり）。VPFD60/61 は一次細分ごと（3つ）。

**発表・継続・解除の表し方**：`Warning/Item/Kind/Status` に「発表」「継続」「解除」「発表警報・注意報はなし」。VPWW54 には前の種別 `LastKind` がある。`ChangeStatus` に「警報・注意報種別に変化有」「警報・注意報種別に変化無、量的予想事項等に変化有」。PDF の凡例では切り替えとして「特別警報からの切替」「危険警報からの切替」「警報から注意報」がある（新体系、2026-06 以降の PDF）。今回の7日間に切り替えの実例は無く、電文での書き方は**確かめていません**。
- 見本：発表 `samples/20261117010549_0_VPWW53_390000.xml`、継続 `…044919_0_VPWW53…`、解除 `…20261116191823_0_VPWW53…`（4:18、強風注意報 解除）、Ｒ０６の解除 `…20261116191810_0_VPWW58…`。
- VPWW53 には新体系に合わせて `Body/Notice`「［危険警報・氾濫特別警報の発表状況］」が足されている。

**訂正・取り消し**：今回の142通はすべて `InfoType` が「発表」、`Control/Status` が「通常」。訂正・取消の実例は無く、**書き方は確かめていません**（防災情報XMLの共通の決まりでは InfoType に訂正・取消などが入る、と理解していますが、今回は資料で確かめていない）。

**時刻の種類**：
- `Control/DateTime`：電文を作った時刻（UTC、秒まで）。ファイル名の先頭と同じ。
- `Head/ReportDateTime`：発表時刻（日本時間、分まで）。警報では `TargetDateTime` も同じ値。
- `Head/TargetDuration`：早期注意の対象期間（VPFD60 P1DT12H、VPFD61 P2DT12H、VPFW60 P4D）。
- `ValidDateTime`・`EventID`・`Serial`：警報の電文では空。
- 注意報の期間は `Property/AdvisoryPeriod/StartTime・EndTime`、山は `PeakTime` に **文字**で（「１７日」「夜のはじめ頃」）。時系列（VPWW54・VPWP50）は `TimeDefines` に3時間ごとの日時。

## B. 判断の材料（保存するならどうするかの案）

### B-1. 何を保存するか（案）

| 案 | 保存するもの | 良いところ | 気になるところ |
|---|---|---|---|
| ① 最小 | VPWW53 だけ | 1通で全要素の今の状態がそろう。今いちばん簡単 | 令和10年度に廃止予定。新しい名前（レベル表記）や危険警報は Notice の文章にしか出ない |
| ② 新旧両方（おすすめ） | VPWW53 ＋ VPWW55〜61 | 並行期間に両方そろえ、廃止後は Ｒ０６ だけで続く | Ｒ０６ は変わった要素しか出ないので、ある時刻の状態は「要素ごとの最新」を組み立てる必要がある（推測） |
| ③ ②＋早期注意 | ＋ VPFD61（と VPFD60、VPFW60） | 「明日・明後日の警報級の可能性」も履歴で比べられる（予報の履歴と同じ考え方） | 1日3通ずつ増える（小さい） |
| ④ 時系列も | ＋ VPWW54、VPWP50 | 市町村ごとの危険度の見通しの移り変わりまで残る | VPWP50 は1通 約1MB。D1 に XML のまま入れるのは重い |

VPWS50（全国の集約、約10分ごと・約1MB）は保存には向かない。取りこぼしの見張り（今の状態との突き合わせ）に使えるかは別の判断（推測）。

### B-3. 取り込み方（案）

- 予報の取り込み（forecastArchive.ts）と同じ形で、`extra.xml`（短い一覧）を毎回、止まったあとは `extra_l.xml`（7日分）を読む。早期注意を取るなら `regular` の側（今の予報の取り込みと同じ一覧）。
- 1通を丸ごと保存し、読み取り（parser）はあとから変えられるようにする（予報・台風と同じ）。
- 高知市の状態は `市町村等` の 3920100、地域の見出しは `一次細分区域等` の 中部（390010）。
- 見張り：警報は「定時」が無いので、予報のような「届かない」判定はできない（推測）。取得の失敗だけを見る形になる。

### B-4. 過去の分（案）

- 2018年からの高知市のおおまかな履歴なら、高知地方気象台の PDF を読み取る方法がある（気象庁の利用規約、出典を書く）。ただし PDF の読み取りは誤りがありうるので、数字は「目安」扱い。
