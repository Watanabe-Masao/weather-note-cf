## 7. 利用の条件（気象業務法・利用規約）

### 確かめたこと
- 予報業務の許可（第17条）が要るのは、観測資料などをもとに **独自に** 予想した結果を **他者に発表する** 業務。気象庁の発表した予報を **解説するだけ** なら許可は要らない（気象庁 Q&A）。https://www.jma.go.jp/jma/kishou/minkan/q_a_m.html
- 数値予報の格子点値を **そのまま** 見せるのは許可不要だが、**空間内挿・高度補正などの加工** をしたり、**特定の地点の予報として** 見せたりすると独自の予報とみなされ、許可が要る（同 Q&A）。予測の方法（自動の計算でも）は問わない。
- 「予報」は観測の成果に基づく現象の予想の **発表**、「予報業務」は予報を **反復・継続** して行うこと（気象庁「外国法人等が行う予報業務の取扱い」の注）。https://www.jma.go.jp/jma/kishou/minkan/tekiyou.pdf
- 気象庁のホームページの値を使うときは出典を書き、加工したら加工したと書く（利用規約、上記）。

### 判断の材料（推測。法律の判断ではない）
- **気象庁の予報の値をそのまま見せる**：出典を書けば、利用規約の上でも、予報業務の上でも問題は少ないと思われる。
- **Open-Meteo の1時間ごとの線を気象庁の最高・最低に合わせて調整して見せる**：Q&A の「加工して特定の地点の予報として見せる」にあたる。**他の人に見せる（発表する）なら許可が要る側** と読める。**渡辺さん一人が使う（2026-11 の判断の「個人利用」）なら「発表」にあたらない** と読めるが、Q&A に個人利用を直接扱う問いは無く、**確かめられなかった**。いまの Open-Meteo の値（地点の予報として見せている）も同じ扱いになると思われる。
- アプリを他の人に見せる・公開するときは、気象庁（情報利用推進課）に聞くのが確実。

## 判断の材料（まとめ）

## 2. 予報業務の許可の線

### 確かめたこと
- 「予報」は時と場所を特定し、観測の成果をもとに科学的方法で予想して、利用者に提供すること。「業務」は反復・継続して行うこと。https://www.jma.go.jp/jma/kishou/minkan/q_a_m.html
- **許可が要らない**（気象の手引き p.1）。https://www.jma.go.jp/jma/kishou/minkan/tebiki/kishou_tebiki.pdf
  - 予想する人が、学校・会社・家庭などでの利用に留め、他者に提供しないとき。
  - 気象庁の予報を解説したり、そのまま伝達したりするとき。
- 数値予報の格子点値（GPV）をそのまま見せるのは許可不要。空間内挿・高度補正などをして**特定の地点の予報として見せる**と独自の予報とみなされ、許可が要る（Q&A）。
- 複数のモデルの結果について「実現性が高い／低い」などを論評すると、独自の予報と受け取られるおそれがある（Q&A）。
- 予想を第三者に反復・継続して発表すれば、手段や営利・非営利を問わず許可の対象（気象庁の説明資料 2014）。

### 判断の材料
- **気象庁の値をそのまま出典つきで出す**（札・ⓘ・◇）：「そのまま伝達」の側。
- **①②**：気象庁の値から選ぶ・引くだけで、新しく予想はしていない。ただ、①を「日の降水確率」として出すと、気象庁に無い予報の要素に見える。だから1の案のとおり「Weather Note の計算」と書くのがよい（推測）。
- **Open-Meteo の補完**：Open-Meteo の値は、モデルを特定の地点に合わせた値。これを地点の予報として出すのは、Q&A の「特定の地点の予報として表示」にあたりうる。
  - **渡辺さん一人や家庭で使う間**は、手引きの「家庭等での利用に留め、他者への提供を行わない」にあたり、許可は要らないと読める（確かめられた範囲）。
  - **他の人に公開する場合**、補完の Open-Meteo の値が「外国の事業者の予報をそのまま伝える」と「特定の地点の予報として見せる」のどちらにあたるかは、**確かめられなかった**。
- A・B・C（ばらつき）は「当たりやすさ」の論評にあたりうる（Q&A の論評の問い）。公開するなら言い方に気をつける（推測）。

### 気象庁に聞くなら（文案。宛先：気象庁 情報基盤部 情報利用推進課）
> 個人で作っている天気のアプリ（無料・広告なし）についてお伺いします。
> 1. 気象庁の府県天気予報・府県週間天気予報（防災情報XML）の値を、そのまま、発表の種類・時刻・地点を添えて表示しています。この表示は「そのまま伝達」として予報業務の許可は不要と考えてよいでしょうか。
> 2. 気象庁の6時間降水確率のうち最も高い値を、その日の降水確率として、「気象庁の6時間降水確率からアプリが選んだ値」と明記して表示することは、独自の予報にあたりますか。
> 3. 気象庁の予報が無い日（8日先以降など）は、海外の事業者（Open-Meteo）が提供する地点の予報値を、出どころを明記して、加工せずに表示しています。これを不特定の人が見られる形で公開する場合、予報業務の許可は必要になりますか。家族だけが使う場合はどうでしょうか。

## 2・3. 探し方と確かめ方
- 何日前のまとまり（1日前／2〜3日前／4〜7日前）ごとに、条件1つと、違う材料の条件2つの組み合わせを全部数えた（まとまりごとに 15〜492 通り、合わせて約 2,800 通り）。

  - 倍率は 1.5 倍以上。
  - 2つの組み合わせは、どちらの1つより 1.1 倍以上高い時だけ残した（言い直しを減らす）。

- 当てはまる件の重なり（Jaccard ≥ 0.5）で、次をまとめた。

# FS-06　予報の動き方をクラスター分析で分ける（2026-11-24）

> **本筋は `fs06b.py`（下の「FS-06（実データでの集計、調査スレッド）」の節）。この節と `fs06.py` は別の作業で積まれたもので、実データで動かして同じ結果になることを確かめた（11/24 渡辺さんの判断）。**

## 実行状況

分析コードは `fs06.py`。手元の人工データでは、月別 ZIP の読み取り、L=3 の判定から L=1・2 の値を除いたこと、時期を分けた分析、表と図の出力を確認した。

高知の実績 CSV 2本はこのブランチにある。shiromatz の予報履歴はリポジトリ内のテスト用抜粋2本まで確認できたが、どの項目・判定日数でも必要な並びがそろった対象日は0件だった。2024年1月〜2026年10月の月別 ZIP がそろった時点で実測データを集計する。2024年1月分は2月初めの対象日を7日前までさかのぼるために必要。高知の残存型、月別の結果、代表図、A〜J との重なり、追加候補は集計待ち。

## 材料と大外れ

- 気象庁の府県・週間天気予報だけを使う。取り出しは FS-05 が使った `fs03.load_forecasts` と `fs04_season.load_wx_pop` を共用し、値のある中でその日の最も遅い発表を採る。判定時点は前日と3日前とし、それぞれ7日前から判定日までの並びを使う。
- 答え合わせは `fs03_obs_47893.csv` と `fs04_rain_47893.csv`。最高・最低は予報と観測の差が絶対値で **2℃超**。雨は **1 mm以上**を降雨とし、見逃しは判定時点の降水確率が50%未満の対象日、空振りは50%以上の対象日を母集団とする。
- 項目ごとに必要な予報が1点でも欠ける日や実績が欠ける日は、その項目・判定日数の分析から除く。雨は降水確率と天気の両方が必要。補間はせず、末端の予報と実績がある日数、および並び全体がそろった日数を記録する。
- 1日前の降水確率は府県予報の6時間値の最大、2〜7日前は週間予報の日値。天気の区域は1〜2日前が高知県中部、3〜7日前が高知県。L=1 の形にはこの切り替えが含まれる。L=3 は全点が週間予報で、L=1 と並べて読む。検証に残った雨の型には、末端の降水確率の構成をそろえた場合の大外れ率も出す。

## 分け方と確かめ方

1. **形の表現**。最高・最低は別々に、各対象日の並びからその日の平均を引いた系列と、隣り合う発表日の差分を比べる。雨は降水確率と天気分類を組み合わせ、値の系列と差分の系列を比べる。天気は晴・くもり・雨・雪を one-hot で表し、異なる分類間の距離を降水確率20ポイント分にそろえる。
2. **モデル選び**。作る期間（2024-02〜2025-10）だけで、k-means、平均連結の階層法、DTW の medoid 法を比較する。DTW は始点と終点を固定し、中の時点は最大1日ずらせる。クラスタ数は2〜6。各クラスタに10日以上ある候補のうち、シルエットが最大値の0.05以内のモデルから、20日以上あるクラスタ間で大外れ率の差が大きいものを選ぶ。新しい対象日は、古い期間で固定した k-means の中心または medoid のうち最も近いものに割り当てる。図には古い期間の各クラスタを代表する実在日を描く。
3. **月と季節**。全年モデルから、各月・各季節の該当割合と、同じ月・季節のふだんに対する大外れ率を出す。別に、四季と各月でモデルを作り直す。月の作る期間が80日未満なら前後1か月、まだ足りなければ前後2か月に広げ、80日を下回る場合は集計を見送る。月単独の確認は確かめる期間の対象月だけで行う。広げた窓全体の成績も別に記録する。月・季節で通った型は、対象月・季節の同じ日付で全年の各クラスタとの Jaccard を計算する。
4. **検証に残す基準**。作る期間に30日以上・大外れ5日以上・ふだんの1.5倍以上の型を検証対象とする。確かめる期間（2025-11〜2026-10）で20日以上・大外れ5日以上・ふだんの1.3倍以上とし、倍率の補正後区間の下端が1を超えた型を残す。倍率の分母は同じ期間・項目・判定日数・範囲における全対象日の大外れ率。7暦日の移動ブロック（5,000回、補正時20,000回）で通常の95%幅と、全年と月・季節の各検証群内で Bonferroni 補正した幅を求める。欠測や雨の母集団の対象外の日が間にあっても、暦日の間隔を詰めない。古い期間に気温の大外れの65%以上が一方向なら、同じ方向が新しい期間も過半数であることを求める。
5. **FS-05 と追加候補**。同じ項目・判定日数・日付で A〜J の該当日を突き合わせ、重複件数、Jaccard、FS-06 側で重なる割合を報告する。L=1・3 の範囲に該当するのは A、B、B'、C、C'、D、G、H、J。固定版 #469 の B（50%以上）の合算も比較対象。E・F・I と4〜7日前の派生型は今回の判定日数の範囲外。全年モデルの検証に通り、既存の型と重なる日が半数未満で、重複日を除いても20日以上・大外れ5日以上・1.3倍以上かつ通常の95%幅の下端が1を超えるものを追加候補とする。雨は末端の降水確率をそろえた大外れ率に対しても1.3倍以上を求める。追加候補はメインが判断する。月・季節ごとの結果は確認期間が1周分なので、暦年を増やして再確認するための材料とする。
