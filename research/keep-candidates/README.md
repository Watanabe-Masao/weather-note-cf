# 後から取れない気象庁のデータの候補（KC-01）

「今は使っていないが、後からでは取れない」データのうち、自前で貯めておくべきものの下調べです。作っていません。
対象外（すでに自前で取っている）：府県天気予報・週間・概況の電文、台風の電文、高知の警報・注意報、天気図、雨雲レーダー。

調べた日：2026-11-17。

- 気象庁の robots.txt は 404（置かれていない、#274）。環境省 熱中症予防情報サイトの robots.txt も **404**（KC-01 で確かめた）。
- 中身は GitHub Actions で **1回だけ** 確かめた（run 44103040257、2026-11-17 23:26 JST、26回の読み込み）。取った中身は保存もコミットもせず、大きさ・種類・時刻だけをログに出した。スクリプトは `kc01.mjs`。使ったワークフロー（`.github/workflows/research-keep.yml`、このブランチへの push でだけ動く、定期実行なし）は済んだので消した。
- 利用条件（気象庁）：気象庁ホームページの利用規約（公共データ利用規約 第1.0版 準拠。出典を書く、加工したら加工と書く）。#274 の README を参照。

## 1. 今後の雨（降水短時間予報）と解析雨量

### 確かめたこと（KC-01）
一覧：`https://www.jma.go.jp/bosai/jmatile/data/rasrf/targetTimes.json`
- HTTP 200、JSON 17,012 バイト、`cache-control: max-age=60`。115行。
- 基準時刻（basetime）は 75個、2026-11-17 02:00〜14:20（UTC）＝ **約12時間分**。
- `member` は `none` と `immed`（速報と思われる。推測）。
- 要素：`rasrf`（1時間雨量）、`rasrf03h`（3時間）、`rasrf24h`（24時間）、それぞれ `_point`・`_nd`。ほかに `slmcs`（線状降水帯）、`sjfcstmap`（線状降水帯の予測）も同じ一覧にある。
- 予報の行の例：基準 14:00（`none`）に対象 2026-11-18 03:00・04:00・05:00 …（1時間ごと、15時間先まで）。
タイル：`…/rasrf/{basetime}/{member}/{validtime}/surf/{要素}/{段階}/{x}/{y}.png`
- 高知市のタイル（段階8 の 222,102）は PNG 256×256。
- 大きさ（ほぼ雨なし）：`rasrf` 526 バイト、`rasrf03h` 423、`rasrf24h` 275、`_point`・`_nd` は 334（何も無い所の共通の画像と思われる。推測）。一覧のいちばん古い（12時間前）の `rasrf` は 1,361 バイト。
- **24時間前（一覧に無い）のタイルは HTTP 404**。ナウキャスト（#274、6時間前でも読めた）と違い、解析雨量は一覧から外れると消える。

出どころ：
- https://www.jma.go.jp/bosai/jmatile/data/rasrf/targetTimes.json （KC-01 で読んだ）
- https://github.com/Watanabe-Masao/weather-note-cf/issues/249 （WX-03：30分ごと、約12時間前〜15時間先）
- https://data.e-gov.go.jp/data/en/dataset/mlit_20140919_0745/resource/6adcdec0-d9c8-46b0-8512-1c94291ce9ea （1km 四方、15時間先まで、7時間先以降は5km）

### 分からなかったこと
- 予報の先の時間ごとの枚数：スクリプトの選び方が悪く、予報（+6時間）のタイルを読めていない（同じ実況のタイルを読んだ）。1回の発表で 1時間ごと15時間先まで（15枚）と思われるが、**確かめていない**。
- 雨の強い日の大きさ（最大 1.4KB しか見ていない）。
- `immed` と `none` の違い、基準時刻が10分ごとに並ぶ理由（30分ごとの解析と10分ごとの速報が混ざっていると思われる。推測）。

### 量の見積もり（段階8 の 3×3＝9枚、30分ごと＝1日 432枚）
| 何を | 1枚 | 1か月 | 1年 |
|---|---|---|---|
| 解析雨量（`rasrf`）だけ | 0.53KB（実測・雨なし） | 7MB | 0.08GB |
| 同上 | 1.36KB（実測の最大） | 17MB | 0.2GB |
| 同上 | 20KB（仮定・強い雨） | 253MB | 3GB |
| 予報も（1回 16枚と仮定） | 1.36KB | 275MB | 3.3GB |
| 同上 | 20KB | 4GB | 48GB |

- 書き込みは、解析だけで月 約13,000回、予報もなら月 約21万回（どちらも R2 の無料分 100万回の中）。
- 置き場所は **R2**（画像なので）。

### 後から取り直せるか
- **約12時間で消える**。24時間前は 404。

### おすすめ
- **解析雨量（1時間雨量 `rasrf`）を30分ごとに貯める**。雨雲レーダー（5分ごと・降水の強さ）と違い「その1時間に何mm降ったか」の面の記録で、アメダスの点の記録を補える。量は年 0.1〜3GB。
- 予報（15時間先まで）は量が10倍以上になるので **後でよい**（予報の当たり外れを比べる使い道が決まってから）。

## 2. 長い先の予報

### 確かめたこと（KC-01、定時の長期の一覧 regular_l、7日分）
| 種類 | 標題 | 7日の件数 | 発表 | 高知（四国）の分 |
|---|---|---|---|---|
| VPCK50 | 地方１か月予報 | 11（各地方1） | 各地方の中枢（四国は高松地方気象台） | 1通（11/12 14:09 JST）。11,511 バイト。Head/Title「四国地方１か月予報」、対象 2026-11-14 から P1M、区域「四国地方」 |
| VPZK50 | 全般１か月予報 | 1 | 気象庁 | — |
| VPCK70 | 地方季節予報（２週間気温予報） | 7（毎日） | 気象庁 | どの地方の分かは **確かめていない**（発表者が「気象庁」で、地方の見分けをスクリプトで付けていなかった） |
| VPZK70 | 全般季節予報（２週間気温予報） | 7 | 気象庁 | — |
| 早期天候情報 | — | 0 | — | 7日間に出ていない |

資料から：
- 早期天候情報の電文は **VPAW51**（XML 一覧表 2026-08-06、平均10KB・最大20KB）。原則 毎週月・木曜に、2週間気温予報の期間に「かなり高い・低い」気温や「かなり多い」降雪を予想したときだけ出る。
- 2週間気温予報は毎日 14:30。
- 確率予測資料（2週間気温予報）の CSV が気象庁ホームページにある（約150地点・24地域、0.1℃単位、1地方 約25KB）。**最新のものだけ**で、過去分は 1991〜2020 年の再予報データだけ。データの利用規約は「気象庁ホームページについて」。
- 1か月予報・3か月予報の電文は 地方：VPCK50、全般：VPZK50（一覧表）。

出どころ：
- https://xml.kishou.go.jp/jmaxml_20260806_format_v1_3_hyo1_1.pdf
- https://www.data.jma.go.jp/suishin/jyouhou/pdf/499.pdf
- https://www.data.jma.go.jp/suishin/shiyou/pdf/no20101
- https://www.data.jma.go.jp/risk/probability/guidance/csv_k2w.php
- https://www.data.jma.go.jp/risk/probability/docs/2weekRefcst-readme.pdf

### 分からなかったこと
- VPCK70（２週間気温予報の電文）の四国・高知の分があるか、その大きさ。
- 確率予測資料の CSV の四国の分の名前（ページの既定は北海道 `2week_t_11.csv`）。
- 3か月予報の電文（7日間に出ていない。月1回と思われる。推測）。
- 1か月予報の確率予測資料（CSV）の置き場所。

### 量の見積もり
- 地方１か月予報（四国）：週1回 × 11.5KB ≒ 月 50KB、年 0.6MB。3か月予報を足しても年 1MB 前後（推測）。
- ２週間気温予報の電文（VPCK70）：大きさ未確認。1通 10〜50KB と仮定すると、毎日1通で年 4〜18MB。
- 確率予測資料 CSV：1地方 約25KB × 毎日 ＝ 月 0.75MB、年 9MB。
- 早期天候情報：出たときだけ、1通 10KB 前後。
- 置き場所は今の予報の電文と同じ（**D1 に丸ごと、R2 に gzip の写し**）。

### 後から取り直せるか
- 電文：長期の一覧に7日。それより後に読めるかは #267 で確かめ中（11/18 朝）。
- 確率予測資料 CSV：最新だけ。**翌日には取れない**。

### おすすめ
- **地方１か月予報（VPCK50、四国）と早期天候情報（VPAW51）を貯める**。今の予報の取り込み（定時の一覧）に種類を足すだけで、量はごく小さい。
- ２週間気温予報は、VPCK70 の中身（高知の地点があるか）を確かめてから。予報の履歴（予報の移り変わり）と同じ使い道があるので、確かめられたら貯める価値は高い。

## 3. 随時の電文（高知県）

### 確かめたこと
資料（技術情報第634号、2026-05-28 から）：
- 記録的短時間大雨情報：**VPOA50**。新しい **VPBS50（府県気象防災速報）** に統合、VPOA50 は移行措置で約2年並行。
- 顕著な大雨に関する情報（線状降水帯）：これまで **VPFJ50（府県気象情報）** の中の「極端現象に関する速報的な情報」。VPBS50 に統合。
- 土砂災害警戒情報：**VXWW50**。新しい **VPWW56（気象警報・注意報（Ｒ０６）（土砂））** に統合、VXWW50 は移行措置で並行。VPWW56 は今の警報の取り込みで **すでに取っている**。
- 竜巻注意情報：**VPHW50・VPHW51** のまま続く（標題が「気象防災速報（竜巻注意）」などに変わった）。

KC-01（随時の長期の一覧 extra_l、7日分）：
- VPHW50・51：全国で各17通、発表は「気象庁」、ファイル名は 390000（高知）。高知の分 各1通（11/17 13:42 JST）。18,527 バイト。Head/Title「高知県気象防災速報（竜巻注意）」。区域は 高知県・西部・幡多・高幡・市町村。
- VPOA50・VPBS50・VXWW50：7日間に全国でも出ていない（「無い」ではなく「この7日間に見なかった」）。

今の警報の取り込み（`worker/src/warningArchive.ts`）でそのまま取れるか（コードを読んだだけ）：
- 読む一覧は随時（extra／extra_l）で同じ。種類（`WARNING_KINDS`）と官署（390000）で選んでいる。
- VPHW50・51・VPOA50・VPBS50 は種類の表に足せば取れる（ファイル名の官署が 390000 であることは VPHW で確かめた。VPOA50・VPBS50 は未確認）。
- **VXWW50 は種類を読み取る正規表現が `VP` で始まる種類だけを見ている**ので、表に足すだけでは取れない（読み取りの直しが要る）。

出どころ：

- https://xml.kishou.go.jp/jmaxml_20260806_format_v1_3_hyo1_1.pdf
- research/warnings/README.md（#267）

### 分からなかったこと
- VPOA50・VPBS50・VXWW50 の高知の実物（ファイル名の官署番号、大きさ）。
- 顕著な大雨に関する情報が、今の VPFJ51（府県気象解説情報）にも出るか。

### 量の見積もり
- どれも出たときだけ。竜巻は 1通 約18KB で、高知は7日で1回。年 数十通・1MB 前後と思われる（推測）。D1 に丸ごと、R2 に写し（警報と同じ）。

### 後から取り直せるか
- 長期の一覧に7日。それより後は #267 で確かめ中。

### おすすめ
- **貯める**：VPHW50・51、VPOA50、VPBS50 を今の警報の取り込みの種類に足す（小さい直し）。土砂は VPWW56 で取れているので、VXWW50 は移行措置の間だけの重なりになる（後でよい）。

### 暑さ指数（WBGT）・熱中症警戒アラート（環境省）

#### 確かめたこと
