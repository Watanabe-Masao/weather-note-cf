## 1. 利用規約（気象庁ホームページについて）

### 確かめたこと
- 権利表記がない限り「公共データ利用規約（第1.0版）」に準拠した条件で利用できる。複製・保存・加工について個別の禁止は書かれていない（公共データ利用規約に従う）。
- 出典の書き方：「出典：気象庁ホームページ（当該ページの URL）」、図は「「図・写真等の名称」（気象庁ホームページより）」。
- 加工した場合（切り抜き・縮小・タイルの組み合わせを含むと考えられる）：出典とは別に加工したことを書く。例「気象庁「図・写真等の名称」（当該ページの URL）を加工して作成」。国が作ったように見せてはいけない。
- 個別の法令の制約として、気象業務法第17条（予報業務の許可）・第23条（警報の制限）に注意、とある。
- 予報・警報などの情報は「常に最新の情報を使う」「発表時刻を確かめる」よう呼びかけている。
- このページには、防災情報のページ（/bosai/）を機械で取りに行くこと・アクセスの頻度・サーバーの負荷についての注意書きは **書かれていない**。
- e-Gov データポータルでは、ナウキャスト（https://www.jma.go.jp/bosai/nowc/）が気象庁のデータとして登録されている（同じ登録の「今後の雨」は「政府標準利用規約（第2.0版）」と表示）。

出どころ：
- https://www.jma.go.jp/jma/kishou/info/coment.html
- https://data.e-gov.go.jp/data/en/dataset/mlit_20140919_0745/resource/a6908863-5726-4e71-bbd7-25f93307dde8
- https://data.e-gov.go.jp/data/en/dataset/mlit_20140919_0745/resource/6adcdec0-d9c8-46b0-8512-1c94291ce9ea

### 分からなかったこと
- 防災情報のページ（/bosai/）の注意書き：ナウキャストのページ（https://www.jma.go.jp/bosai/nowc/）を Web の読み取りの道具で読んだが、取れた文字はタイトルと説明文だけで、注意書き・ご利用にあたって・機械での取得についての記述は **見当たらなかった**。ただしこのページは中身を JavaScript で出すので、画面に出る注意書きまでは読めていない（「無い」とは言えない）。

## 3. 雨雲レーダー

### 確かめたこと（すでにある記録から。今回は読み直していない）
#249 の WX-03（2026-11-17、Actions で気象庁の一覧 `targetTimes` を読んだ結果）より：
- 「雨雲の動き」（ナウキャスト）は **5分ごと**。降水の強さ（`hrpns`＝高解像度降水ナウキャスト）、雷・竜巻（N3：`liden`・`thns`・`trns`）。
- 気象庁の一覧に残るのは **約3時間分**。それより前は一覧から外れる。
- 「今後の雨」（解析雨量・降水短時間予報 `rasrf`）は 30分ごと、約12時間前〜15時間先。
- どれも **256px の地図タイル**で、1枚の画像ではない。
- 一覧の置き場所：`www.jma.go.jp/bosai/jmatile/data/nowc/targetTimes_N1.json`（実況）・`_N2`（予測）・`_N3`（雷・竜巻）、`…/jmatile/data/rasrf/targetTimes.json`。

ほかの出どころから：
- 高解像度降水ナウキャストは 2014年8月に始まった（それまでの降水ナウキャストは 2004年夏から、1km、1時間先まで）。
- 「今後の雨」は 1km 四方の解析と15時間先までの予報（7時間先以降は5km）。
- 気象庁のナウキャストのタイルを取る仕組みを作った第三者のライブラリがある（地点と拡大の段階からタイル番号を出す）。気象庁の公式の説明ではない。

出どころ：

- https://www.jma.go.jp/jma/en/Activities/qmws_2018/Presentation/3.1/High-resolution%20Precipitation%20Nowcasts.pdf

### 確かめたこと（RD-02、Actions で1回）
一覧：`https://www.jma.go.jp/bosai/jmatile/data/nowc/targetTimes_N1.json`
- HTTP 200、JSON 3,667 バイト、`cache-control: max-age=60`。
- 37件、**5分ごと**、`basetime`＝`validtime`（実況）、2026-11-17 10:10〜13:10（UTC）＝ **ちょうど3時間分**。要素は `hrpns`（高解像度降水ナウキャスト）と `hrpns_nd`。時刻は UTC の `yyyyMMddHHmmss`。

タイル：`…/nowc/{basetime}/none/{validtime}/surf/hrpns/{段階}/{x}/{y}.png`
- 形式：**PNG 256×256**（ほとんどが 4ビットのパレット色）。`last-modified` は時刻の約30秒後。
- 段階6・8・10 の高知市のタイル、段階8 の 3×3 枚（221〜223, 101〜103）が、どれも HTTP 200。

### 分からなかったこと
- 強い雨が広く降っているときの1枚の大きさ：今回は雨がほとんど無く、**最大でも 5.4KB** しか見ていない。
- 段階6〜10 以外（上限・下限の段階）があるか：読んでいない。
- 6時間より前（何日前まで）タイルが残るか：1回だけの決まりなので確かめていない。
- 「表示だけ」と「保存する」の両方について：規約（1.）からは、出典と加工の表示をすればどちらも認められる書き方。/bosai/ の注意書きは見つからなかった（JavaScript で出る分は未確認）。**禁止は見つからなかったが、「問題がない」と言い切れるほどには確かめられていない**。

## 4. 量と費用の見積もり（RD-02 の実測で）

条件：降水の強さ（`hrpns`）の実況だけ、高知のまわり段階8 の 3×3＝9枚、1時間ごと（1日24回、216枚）。1枚の大きさは、実測の **平均 0.55KB（雨なし）**、実測の最大 **5.4KB（少し雨）**、強い雨を見込んだ仮定 **20KB（前の見積もり、推測）** の3通り。

| 1枚 | 1日 | 1か月 | 1年 | 10年 |
|---|---|---|---|---|
| 0.55KB（実測・雨なし） | 0.12MB | 3.5MB | 0.04GB | 0.4GB |
| 5.4KB（実測の最大） | 1.1MB | 34MB | 0.41GB | 4.1GB |
| 20KB（仮定・強い雨） | 4.2MB | 127MB | 1.5GB | 15GB |

- 実際には雨の日と無い日が混ざるので、**1年で 0.1〜0.5GB くらい**になると思われる（推測）。前の見積もり（20KB で年1.6GB）は大きすぎた。
- 書き込み（R2 の Class A）：216回／日 ＝ 約6,500回／月（大きさによらない）。

### R2 の料金
- Standard：保存 $0.015／GB・月、Class A（書き込み）$4.50／100万回、Class B（読み出し）$0.36／100万回、外への転送は無料。
- 毎月の無料分：保存 10GB・月、Class A 100万回、Class B 1,000万回。

出どころ：
- https://developers.cloudflare.com/r2/pricing/

### 費用の目安（計算）
- 書き込みは月 約6,500回で、無料分（100万回）の1%未満。
- 保存は、今の予報・電文・天気図の保存（すでに R2 にある）と合わせて 10GB を超えるまでは無料。実測の大きさなら、レーダーだけで10年分でも 0.4〜4GB で、10GB に届かない。
- 仮定の上限（20KB）で10年分（15GB）を持っても、無料分を引いて月 約 $0.08（約12円）。
- R2 の料金は Workers Paid（月 $5）とは別に数えられ、無料分は R2 自体の分（Workers Paid に含まれる分ではない）。どちらにしても、この量では R2 の費用はほぼかからない。

## 5. おすすめ

- **「表示だけ」で始める**のがよい（推測を含む）。
  1. 規約上は表示も保存もできる書き方で、robots.txt の禁止も無いが、/bosai/ の画面に出る注意書きは確かめきれていない。表示（見る人の端末が必要な分だけ読む）のほうが、定期的にまとめて取る保存より負荷も責任も小さい。
  2. 表示は「最新を使う」という気象庁の呼びかけに合う。
  3. 保存しても量・費用はとても小さい（年 0.1〜0.5GB、R2 の無料分の中）ので、あとから足しても困らない。
- 保存を足すときの注意：一覧は3時間分だけ。6時間前のタイルは読めたが、それより前は確かめていないので、**取りこぼしたら取り直せない前提**で作るのが安全（推測）。
- 表示でも保存でも、画面には「雨雲の動き（気象庁ホームページより）」、切り抜き・重ね合わせたら「〜を加工して作成」と書く。時刻（UTC の名前を日本時間に直す）を必ず添える。
