# Weather Note デザインシステム

見た目と操作のルール。値は `src/design/tokens.ts` が唯一の出どころで、`applyTokens()` が CSS 変数（`--surface-*` など）として配ります。
`styles.css` に生の色・時間・z-index を書かないこと。

## 1. 原則

**最上位の原則（ブランド・基調配色の設計思想、2026-11-16）**：「自然を観察し、自分を理解する」道具として、人間の知覚を基準に、静けさ・自然さ・知性・繊細さ・個人への適応が調和する体験をつくる。色・文字・グラフ・アイコン・動きの判断はすべてこれに従う。

- **3つの基調色は一つのブランドの3つの表情**：Deep Navy（深さ：静寂・知性 #101B2C）、Mist Green（自然：調和・穏やかさ #C4D0C1）、Warm White（光：柔らかさ・明瞭さ #F7F5F0）。どれも原色を避け、彩度を抑える。
- **3色は互いの性格を取り入れる**：Deep Navy の文字は Warm White 由来の温かい白、Warm White の文字は Navy 由来の深い色、アクセントは全テーマで Green 由来。
- **変えてよいもの**：背景の明るさ、色相・彩度の微調整、文字や枠線の実際の色値、テーマごとの雰囲気、視認性のための補正。**変えてはいけないもの**：ブランドの品位、気象要素の色の意味、情報の優先順位、操作・比較の一貫性、読みやすさと信頼性。
- 判断は色そのものの美しさだけでなく、周りとの関係・錯視・情報の優先順位・画面全体の印象で行う（数値の検証と実機での見え方の両方）。

- **比較が主役。** 対象日と比較日は、いつも同じ並びにする（左／上が対象日、右／下が比較日）。どちらかを強く見せるときは、比較日を少し控えめにする（線は主の線の距離の 80% になる不透明度、テーマごとに決める：下の「役割ごとに背景からの距離を揃える」）。
- **シンプルに、でも豊かに。** 装飾は足さない。奥行きは、ごく薄いグラデーション、柔らかい影、アクセントのにじみ（中央の帯）だけで出す。
- **1つの意味には1つの見た目。** 色、線種、閉じ方、単位の書き方は全画面で同じにする。

## 2. 色

| 役割 | トークン | 使う場所 |
| --- | --- | --- |
| 面 | `surface.page / base / raised / overlay / inset` | 背景 → カード → 浮いたシート → 入力欄やへこんだ面 |
| 文字 | `ink.primary / secondary / tertiary / disabled / onAccent` | 本文 → 補足 → ラベル・単位（補足と同じ明るさ。暗い背景で読みやすさを優先：比較ページで 3 を選択）→ 欠測 → アクセント上の文字 |
| 線 | `line.soft / strong / focus` | 区切り → 枠 → フォーカス |
| アクセント | `accent.base / strong / wash / glow` | 選択中（チップ・帯・カレンダー）だけ |

**データの色（DATA）は 1色につき意味が1つ。**

| 色 | 意味 |
| --- | --- |
| `hot` | 最高気温 |
| `cold` | 最低気温 |
| `mean` | 平均・気温（参考線） |
| `rain` / `snow` | 降水量 / 降雪 |
| `sun` | 日照（日照時間と明るさ） |
| `radiation` | 日差し（日射量）。日照の黄色と分ける橙 |
| `humidity` / `humidityLow` | 湿度 / 湿度の最小（同じ色の濃い方） |
| `wind` / `gust` | 風速 / 最大瞬間（同じ色の淡い方） |
| `pressure` / `pressureHigh` / `pressureLow` | 気圧 / 気圧最高（淡い砂）/ 気圧最低（濃い茶） |
| `feel` | 肌感（日なた・日かげ） |

- 対象日と比較日は**色で分けない**。線は実線（対象日）と破線（比較日）、棒は塗り（対象日）と枠線（比較日）で分ける。
- **線の種類は「どちらの日か」だけを表す。** 予報かどうかで線の種類は変えない。予報の日や時間は、グラフの背景を網かけにし、その上端に「予報」と書いて示す。
- **表の肌感の帯（`FeelBar`、`FEEL_BAND`）：** 1本の帯で、角は少しだけ丸める（`radius.xs`）。時間帯の色は帯のグラデーションで、境目は帯1つの幅の 22% でぼかし、その上に面の色の細い区切り（1.5px）を入れる（時間帯は数えられるが、硬いタイルにはしない。区切りの隙間を 2px にした案は広すぎた）。予報の時間帯は細い網（面の色 12%）。日別の値からの目安（3つ）は点線で囲む。**今日の列だけ**、今の時間帯を白い輪（1.5px）で囲む（1分ごとに動く）。輪は「今日」の印と組で使う（下の 4 の `DayLabel`）。
- 肌感の7段階は `FEEL_LEVELS`（7色）を使い、5段・3段の簡易表示は `FEEL_SCALE_COLORS[5]`／`[3]` を使う。どれも「段階の目盛り」なので、マスや背景の塗りにだけ使い、線には使わない。色と名前は `levelColor`／`levelName`／`legendOf`（`FeelBar.tsx`）から取り、段数ごとに書き分けない。
- 段階の名前は短くする（チップやマスに収まる長さ）。7段は 寒い／肌寒い／涼しい／暑くも寒くもない／暖かい／少し暑い／暑い（感じ方の記録と同じ言葉。涼しい〜暖かいが快適）。5段は 寒い／涼しい／暑くも寒くもない／暖かい／暑い、3段は 寒い側／ちょうどよい（涼しい〜暖かい）／暑い側。
- 空の色（模式、`shared/sky.ts`）はデータ色でも段階の色でもない「絵」の色：「明るさと空」の帯（色の明るさは明るさの段に合わせ、下の細い線を段の色にする）、読み取りの見本、時間帯のグラフの下の「太陽」の帯（その日の天気の空）、太陽のシートの地（晴れた日の空）にだけ使い、ほかの意味は持たせない（#151）。必ず「模式」と書き、写真や実測と取れる言い方をしない。「太陽」の帯は帯の右端（夜の上）に「空は模式」と書く。空の上の白い線（太陽の高さ）には暗い縁（`surface.page` 55%、幅 3.2）を付け、どの空の上でも読めるようにする（#173）。指でなぞる帯とその拡大カードは文字の選択・長押しメニュー・拡大鏡を出さない。
- 時間区分（朝・日中・昼・夕方・夜）の線は `BAND_LINES`（明るさの違うグレー系）と `BAND_MARKS`（●■▲◆○）を使う。データ色や段階の色とは重ねない。
- **色は項目ごと（#151）。** 項目を切り替えたら色も変わる。最高と最低のある項目は同じ色の淡い（高い方）・濃い（低い方）で分ける。気温の最高・最低だけは赤と青（暑い・寒いの読みが自然なため）。ほかの項目に気温の赤・青を借りない。
- **差（+3、−2）には色を付けない。** 赤と青は「最高／最低」の意味なので、「暖かい／寒い」の意味には使わない。大きな差（3以上）は太字で目立たせる。
- 土曜は `day.saturday`、日曜・祝日は `day.holiday`。日付と曜日にだけ使う。
- 状態の色：予報 `status.forecast`（色味のない灰）、暫定 `status.provisional`、エラー `status.error`。
- **アクセントは「選んでいる」印だけ（#151、テーマでは緑、#241）。** 選んだ日の枠・選んだチップ・押している項目。予報やフォーカスの輪と同じ青を使っていたため、予報の範囲と選んだ日が混ざって見えていた。予報は「まだ測っていない」ので色味を持たない灰にする。

### 2.0b テーマ（#241）

**3つのテーマを同じ構造で持つ**：Deep Navy（暗い）／Mist Green（穏やかな緑）／Warm White（明るい）。設定の「表示 → テーマ」で選び、「自動」は iPhone の明るい／暗い設定で Warm White か Deep Navy。この端末に保存する（`src/design/theme.ts`）。

- 値は `src/design/tokens.ts` の `THEMES`。CSS は `applyTheme` が書く変数で、SVG のグラフは同じ関数が中身を入れ替える `DATA`・`FEEL_LEVELS` などで読む。切り替えると全体を描き直す（開いているシートは閉じない）。
- **同じ意味は同じ強さで**（再設計書 v1.0）：色相は項目ごとに全テーマで同じ。明るさだけをテーマごとに変える。文字は 4.5:1、データの色は数字として読むので 4.5:1、状態の印（アクセント・警告・エラー・予報・時間区分の線）は 3:1（`test/ui/themes.test.ts` で全部確かめる）。
- **アクセントは緑**（3テーマ共通の役割、操作と選択だけ）。緑に近かった湿度は青緑に移し、アクセントから ΔE 10 以上離す（ほかの項目は 7 以上）。
- **肌感7段階は3テーマで同じ色（鮮やかな塗り＋白い数字＋内側の縁）**（2026-11-18、渡辺さん「寒い＝#3232FF をベースに色の表」「枠の内側を数ピクセル #3265FF のグラデーション」「Warm White とグリーンも合わせて見直し」）：段は**明るさではなく鮮やかさ**で分ける。寒い・暑いがいちばん鮮やか、ふつうがいちばん落ち着く（対の段は同じくらい）。寒い→暑い：`#3232FF` `#0072E5` `#007DB0` `#547E5D` `#A46700` `#BD5700` `#E22919`。どの段も白い数字（`ink.onFeel`）が 4.5:1 以上で読める明るさにし、3テーマで同じ色を使う（温度の色はテーマで変えない）。**肌感の塗り（面）**：数字を載せる面（肌感マップのマス、月の振り返りの肌感の帯）は、段の色で塗り、枠の内側に各段の少し明るい色（`feelEdge`、寒いは `#3265FF`）を 4px でぼかして入れ（`FEEL_CELL`）、数字は白にする。必ず `feelFillLook(color)` と CSS の `.feel-fill` で塗る（自前で縁を書かない。`test/ui/feel-fill.test.ts` が見張る）。凡例や行の頭の小さな見本（12px 以下）は縁を付けない（ぼかしで色が見えなくなる）。カードの上でも 2:1 以上。5段は 1・3・4・5・7、3段は 2・4・6 を使う。以前（#242、2026-11-17）は base からの距離 4.4・3.6・2.9・2.4・2.9・3.6・4.4 で段を分けていたが、Deep Navy の上で暖かい側が茶色・黄土色になり、温度感が伝わらなかった（暗い面では黄・橙は明るくないとその色に見えない）。
- **同じ強さに見えるように、透明度もテーマで変える**（再設計書 7.3）：同じ不透明度でも明るい面ではずっと薄く見える。ただし天気の絵と参照線・網かけ・グリッドは透明度で弱めない（下の2項目：不透明の色や線の細さ・点線で控えめにする。`effect.quiet / estimated / estimatedQuiet` は3テーマとも 1）。シートの後ろのぼかしは、明るいテーマでは暗くせず地の色で包む（暗い膜は汚れに見える）。
- **役割ごとに背景からの距離を揃える**（#243 の考え方、2026-11-17）：グラフの役割ごとに、3テーマで同じコントラスト（base に対して）にする。主の線と数字（最高・最低）5.0 前後（raised でも 4.5 以上）、比較日はその線を主の線の距離の 80% になる不透明度（テーマごと：Deep Navy 0.89・Mist 0.89・Warm 0.90、`compareOpacity`）、参照線（手前1週など）2.4、予報の網かけ 1.6、グリッド 1.3。どれも不透明の色（`chart.grid / hatch`、`reference`）で、透明度で弱めない。順番「主 ＞ 比較 ＞ 参照 ＞ 網かけ ＞ グリッド」をテストで確かめる。
- **最高・最低の色は3テーマで同じ色の意味**：明るいテーマは同じ色相・同じ鮮やかさ（レンガの赤と深い青）。Deep Navy は下の項目の通り、赤をテラコッタに寄せる。Deep Navy で光ってピンクに見えていた赤は、テラコッタになる。ほかの項目の色（降水・日照など）は今のまま：黄色は明るくないと黄色に見えないなど、色相ごとに明るさの決まりがあるため、同じ距離に揃えると色の意味が崩れる。
- **Deep Navy の色は「印象」で合わせる**（#244、2026-11-17）：何色に見えるかは彩度の量でなく**鮮やかさの割合（彩度÷明るさ）**で決まる。暗い地で数字が読める明るさの赤は、明るいテーマと同じ色相ではサーモンに、割合を揃えると鮮やかすぎて浮く。そこで Deep Navy の最高・最低は、明るいテーマの割合の **85%** にし（2026-11-17 は 68%。面を深くした 2026-11-18 に、夜に見てくすんでいたので上げた。60% はくすんで灰色がかった）、赤（最高）だけ色相を**茶へ 10°**寄せて**テラコッタ**にする（明るいテーマのレンガの赤の、暗い地での姿）。コントラストは、明るいテーマと同じ 5.4 前後から、**Deep Navy だけ 6.5（カードの上で 5.8）** に上げた（2026-11-18）。暗い地の上の色のついた数字は、比の数字ほどには読めない（APCA で測ると、比 4.5 で Lc 35。比 6.5 で Lc 45）。夜に見ると読みにくかったため、鮮やかさの割合（85%）と色相はそのまま、明るさだけ上げた。APCA は基準にはしない（WCAG 3 の下書きから外れ、計算方法が未定。#244）。説明の文字（secondary・tertiary）も同じ理由で `#B8B4AA` に上げた（Lc 54 → 60）。寄せすぎると晴れの絵（黄土）・日射（橙）と近くなり、「暑い＝赤」の意味が崩れる（24° は不採用）。天気の絵は以前の Deep Navy の色から彩度を 70% に下げた（コントラストは 6.0 のまま。面を深くしたときに明るさを解き直した）。サンプルを実機で見比べて決めた。線だけ深く・数字は明るく分ける案もよく見えたが、「最高」の色が2つになり決まりの管理が複雑になるため採らない（1つの役割に1色）。
- **天気の絵は薄くしない**：比較日の絵は細い線（1.65、対象日は 1.9）、推定は点線で示す（透明度で控えめにすると、明るい面で消えかける）。絵の色は3テーマで同じ色相で、線は背景から Deep Navy 6.0・明るいテーマ 4.6（暗い面では同じ数値でも細く・ぼけて見えるため、Deep Navy を少し遠くする）。
- **天気の絵は塗り＋線**（#242）：塗りは色を持たず、置かれた面に掛ける薄い膜（`effect.veil`：Deep Navy は白 5%、明るいテーマは黒 6.5〜7%）。面の色が透けるので、カード・シート・沈んだ面のどこでも「面より少し沈んだ（浮いた）塗り」という同じ関係になる（不透明の灰色にすると、周りの色との対比で面ごとに違う色に見える）。
- **面の距離は3テーマで同じ数値**（#242、Warm White を基準）：OKLab の明るさで base から カード（raised）+5.0、浮いたシート（overlay）+5.5、沈んだ面（inset）−2.5。Deep Navy だけカードが遠く見えていたのを揃えた。テストで確かめる。
- **Deep Navy の面は深いネイビー**（2026-11-18、渡辺さん「夜に見ると色がくすみすぎ。もっとディープなベースに」）：base `#041029`（OKLCH の明るさ 0.18。以前は `#172337`、0.26）。カード・シート・沈んだ面は上の距離のまま、グラフの参照線・網かけ・グリッド・強い線・天気の絵は、決まりの距離のまま新しい面に合わせて解き直した。比べるサンプルを実機で見て決めた（案4）。
- 空の色（`LIGHT_LEVELS`、模式）はテーマで変えない「絵」の色。

## 2.1 文字の大きさ（`size`）

文字の大きさは、役割で決めた7つの段だけを使う。0.5px 刻みの大きさや、段の間の大きさは作らない。

| 段 | px | 役割 |
| --- | --- | --- |
| `xs` | 11 | 注記・単位・状態の札（実績／予報）・信頼度・軸の目盛り（iOS Caption 2） |
| `sm` | 12 | ラベル・補足・小さいチップ（iOS Caption 1） |
| `base` | 13 | 本文・ボタン・チップ（iOS Footnote） |
| `md` | 15 | 値（表・読み取り）・小見出し（iOS Subheadline） |
| `lg` | 17 | 見出し・強調する値（iOS Headline／Body） |
| `xl` | 20 | いちばん大きい値（iOS Title 3） |
| `input` | 16 | 入力欄だけ（16 未満だと iPhone が拡大する） |

- 段は iOS の文字スタイル（標準の文字サイズ設定のとき）にそろえる。太字は iOS の Semibold（600）：ヒラギノは W3／W6 しかないので、600 なら漢字と数字の太さが一致する。
- **画面に 11px（`xs`、iOS のいちばん小さい文字）より小さい文字は出さない。** 単位も例外にしない。幅が足りないときは、文字を小さくせずに、余白や書き方で収める。
- SVG の中の文字は、描かれた幅から画面上の大きさを計算し、`TYPE_SIZE` の段に合わせる（共通のフック `useDrawnWidth` と `svgTextSize`、`src/ui/useDrawnWidth.ts`）。SVG の中では大きさが描く幅の単位になり、縮めて描くと 11px を下回るため。
- 親の大きさに合わせて1段下げたいとき（日付の曜日など）は `max(var(--size-xs), 0.86em)` のように、`xs` を下回らない形で書く。
- 見張り：`test/ui/tokens.test.ts`（段以外の大きさを書かない）、e2e の「11px より小さい文字がない」（表・時間帯・設定・肌感マップ）。

## 2.2 余白（`space`）

余白（padding・margin・gap・位置のずらし）は `space` の9段だけを使う：`--space-1`〜`--space-9` = 2・4・6・8・10・12・16・20・24px。

- 段の値（例：8px）を数字で書かない。`var(--space-4)` と書く。負の値は `calc(-1 * var(--space-2))`（#266 で置き換え済み。見張りの一覧で 0 を保つ）。
- 段にない値（3px・1px・5px・14px・18px など）は、今は段を足さない。下の「直書きの見張り」の一覧に載せ、増やさない。近い段に寄せる（見た目が少し変わる）ときは、画面ごとに見本で確かめてから。
- 寸法（幅・高さ・押せる大きさ）は余白ではない。決まった大きさは部品の決まり（4 章）に書く。

## 2.3 線の太さ

線は役割で太さが決まる。今使っている太さと役割：

| 太さ | 役割 |
| --- | --- |
| 1px | 区切り・枠（`line.soft`／`line.strong`）、カードの縁、選択の輪の外側 |
| 1.5px | 選んでいる枠（表の中央の枠・グラフの選んだ日の枠）、強調の輪 |
| 2px | フォーカスの輪（`outline`）、操作のアイコンの線、回る輪、強い区切り（予報の境など） |
| グラフの値の線 | `lineLook`／`barLook` から受け取る（4.1。部品の中で太さを書かない） |
| 天気の絵 | 1.9（比較日 1.65、4 章） |

- 線の太さのトークン（2026-11-18）：`STROKE`（CSS は `--stroke-hair` 1px・`--stroke-select` 1.5px・`--stroke-focus` 2px）。新しく書く線はこれを使う。古い所の数字は一覧（hardcode-budget）に載っていて、増やさない・減ったら一覧も下げる。
- 同じ役割の線を別の太さで描かない（「1つの意味には1つの見た目」）。役割がそろっていない所（グラフの選んだ日の枠が表と違う、など）は、見本で確かめてからそろえる（B）。

## 2.4 透かし

- 透かしの色は `color-mix(in srgb, var(--トークン) N%, transparent)` で作る（8 章）。生の `rgba(…)` は書かない。
- 割合（N%）と `opacity` の値は、まだトークンにしていない。一覧に載せて増やさない。同じ意味（選んでいる薄塗り・予報の網など）で割合がばらけている所は、役割の名前を付けてそろえる（B、見本で1つずつ）。
- グラフの役割（比較日・参照線・網かけ・グリッド）は透明度で弱めない（2.0b）。

## 3. 数値・単位・日付（`src/design/format.ts`）

- 単位は数値の後ろに小さく付ける（`.unit`）：℃、mm、cm、%、m/s、hPa、MJ/㎡、h。数字が縦に並ぶ表（読み取り・比較の要約）では、単位は行の名前の後ろに1回だけ書き、数字には付けない。
- **数字の格子（#151 一文字ずつ）。** 数字が縦に並ぶ所では、数字を右そろえ（`tabular-nums`）にして小数点を縦の1本にそろえる。列の中では一つの幅の箱に入れ、箱を列の真ん中に置く（表・条件の表：「00.0」の幅）。一つの表示の中では小数の桁をそろえる：比較の要約は湿度・気圧も小数1桁（62.0 %、1016.3 hPa、差 +6.0）。欠測の「—」は列の真ん中。4桁（気圧）は表で1段小さくして、隣の日とくっつけない。カレンダーの最高気温は数字をマスの真ん中に置き、C の札は数字の右に掛ける（札で数字がずれない）。
- 小数点以下の桁数は単位で決まる：℃ 1、mm 1、cm 1、% 0、m/s 1、hPa 0、MJ/㎡ 1（1時間ごとの値だけ 2）、h 1。1時間ごとの日照は「40分」と書く。
- 差は `signedDiff`：「+1.2」「−0.4」「±0」。マイナスは全角の「−」。どちらかの値がなければ空にする。
- 欠測は「—」（`ink.disabled`）。
- 日付は0で埋めない：「11/9（月）」。年を付けるのは、比較日が対象日と別の年のときと、見出しだけ。
- 年の形は2つ（`format.ts`）。**長い形**「2025/11/10（月）」（`dateLabel` の year）は日を選ぶ所と見出し：表の日付ボタン、比較の要約の見出し、カレンダーの組み合わせ。**短い形**「’25/11/10」（`shortDay`、`yearMark`）は狭い列の頭・畳んだ1行・文の中で、対象日と年が違うときだけ付ける。記号は「’」（U+2019）で、半角の「'」は使わない。
- 軸の目盛りは `niceTicks(lo, hi, 5)` を使って、4〜6本の切りのいい値にする（5 / 10 / 15 / 20）。どのグラフも同じにする。単位は軸の上に書く。

## 4.1 グラフの共通ルール

- **背景は予報だけ。** 予報の日や時間は網かけにし、上端に「予報」と書く。選んでいる日は背景を塗らずに枠で囲む（表の中央の枠と同じ意味）。
  - 網かけの線は「予報」の文字と同じ灰（`status.forecast`）を薄くしたもの（線 24%・地 4%）。グラフ・カレンダー・凡例の見本で同じ色を使う（比較ページで E を選択）。
- **読み取りカード（`GraphReadout`）。** グラフの真上に置き、「何の値か・対象・比較・差」を同じ列で示す。指を離している間は、選んでいる日（または時刻）の値を出す。
  - 日別のグラフのカードには、下に**時間帯の天気**（朝・日中・昼・夕方・夜）を置く（`PartsWeather`）。時間帯の天気の帯と同じく、大きい方が対象・小さい方が比較、推定（日照と降水から）は薄く。指で日をなぞると、その日の天気に変わる。
- **グラフの下はすっきり（日別）。** 日付の行は、比較日がすべて同じ日付（前年同日）なら1行にし、比較の年はカードに書く（'25/11/10）。違う日付（前週・前年同曜日・カスタム）の時だけ「対象／比較」の2行。凡例は1行（対象日・比較日・予報）で、その端の ⓘ に信頼度と項目ごとの注記（寒暖差・肌感・降水確率・瞬間・日照の数字）をまとめる。線のチップは1行で、入りきらなければ横に送る（右端を薄くして続きを示す）。
- **日別のグラフはシートに収める。** グラフの高さは、シートの中の残り（カード・切り替え・凡例・チップ・注記を除いた分）を**測って**決め、縦にスクロールさせない。足りない時（低いシート）だけ、グラフの最小（150）を守ってスクロールする。軸は見えている7日と両隣の1日で決める（遠くの日に引っ張られて軸が 0 まで伸びない）。
- **触っている所に補助線（`GuideLines`）。** 指の位置に縦線を引き、対象日の点から値の軸まで点線を引く。点線が軸に当たる所には、線と同じ色のタグで値を出す。タグ同士が近いときは、重ならないように上下にずらす。触っている間は、読み取りカードの枠が光る。
  - 時間帯と推移のグラフは、触れたらすぐ補助線が出る。
  - 日別のグラフは横スワイプで日を動かすので、長押し（0.28秒）すると補助線が出て、そのまま指を動かせる。マウスでは、ポインタを乗せるだけで出る。
  - 長押しで iPhone の拡大鏡やコピーのメニューが出ないよう、アプリ全体で文字の選択と長押しメニューを止めている（入力欄だけは除く）。
- **線の決まり（`lineLook` / `barLook`、`src/design/tokens.ts`）。** グラフの線と棒は、必ずこの2つの関数から見た目を受け取る。破線の間隔や太さを部品の中で書かない（`test/ui/lines.test.ts` が見張る）。
  - **どちらの日か＝線の形。** 対象日は実線、比較日は破線。棒は対象日が塗り、比較日が枠線。色では分けない。
  - **何の線か＝色。** その日の値は項目のデータの色。その日に添える基準（手前の平均、肌感の後ろの気温など）は参照の色（`LINE.reference`：テーマごとの不透明な灰。背景から 2.4 で、比較日の線より弱い）で、値の線より細くする。線の形はその日のものに合わせる（対象日の平均は実線、比較日の平均は破線）。
  - **脇に置いた線＝グレー。** 凡例で薄くした線は暗いグレー（`LINE.dimmed`）で細くし、不透明度 0.55 にするが、線の形は残す（0.8 では参考線を薄くしても変化が小さかった、#173）。
  - **2本目の系列（日別の「平均」など）は細く（`weight: "minor"`）。**
- **質感：少しだけ角を取る（`SHAPE`・`barPath`、`src/design/tokens.ts`）。** 印の角は柔らかくするが、値の終わりが分からなくなるほど丸くしない。
  - **量の棒**（降水量・日射量・日照、日別も時間帯も）：上の角だけを丸め（半径 3）、足は 0 の線に四角く置く（0 からの長さが読める）。細い棒・短い棒は丸みを小さくする（幅の 1/4・高さまで）。丸くしすぎると錠剤の形になり、棒に見えない。棒は必ず `barPath` で描く（`test/ui/lines.test.ts` が見張る）。凡例の見本も同じ形。
  - **幅の棒**（気温の「幅」）：1日の最高〜最低を1本の棒にし、両端を丸める（両端とも値で、丸みは棒の内側なので先端が値）。対象日は最高の色から最低の色へのグラデーションの塗り、比較日は同じ色の枠線で右に並べる（どちらの日かは塗り／枠線）。平均は白い短い印。最高の値は棒の上、最低の値は棒の下に書く。
  - **線の継ぎ目**：1日（1時間）ずつの線分ではなく、途切れない区間を1本の線で描き、角を丸める。比較日の破線のリズムが日をまたいで続く。欠けた日で線は切れる（つながない）。
  - **値の文字**：日別の線グラフでは、対象日の主な線の値を点のそばに書く。組の高い方（最高・平均湿度）は点の上、低い方（最低・最小）は点の下、1本だけの線（風速）は山なら上・谷なら下。枠からはみ出すときは反対側。文字は項目の色・`xs`・等幅で、後ろの面の色の縁取りを付ける（線が数字を切らない）。比較日・平均・肌感・基準の線には書かない（読み取りカードで読む）。文字が収まるよう、軸の上下に文字の高さ分の余白を取る。時間帯のグラフ（24点）には書かない。
  - **格子**：値より一歩下がる。細かい点線（2 5）で、濃さ 55%。
- **気温の「線」と「幅」**：気温の日別だけ、見出しの下の切り替え（`Segmented`）で、線と幅を選べる（この端末に覚える）。幅のときは最高・最低のチップを出さない（棒そのものが最高〜最低のため）。寒暖差のチップは下の数字の行だけを切り替える（帯の網は棒と重なるので描かない）。ほかの項目は幅にしない（気圧・湿度の最高と最低は「1日の幅」として読むものではないため）。
- **気圧の平均は初めは出さない**（最高・最低と比較日で線が4本あるため。凡例のチップで出せる）。
- **凡例はグラフ（マップ）の真下に置く。** 文章ではなく、グラフと同じ見本（線・塗り・網かけ）で示す。肌感の段階の色は、肌感の画面の一番下にまとめる。
- **面はどのグラフも同じ（#151）。** 目盛りの線・予報の網かけ・選んだ日の枠（`chart-center`）だけ。値の段（肌感の段・明るさの段）の色は面に敷かず、軸の横の細い帯と境目の線で示す（`LevelScale`）。段の名前は切らずに出す（入らないときは2行、2行も入らないときは出さない）。
- **日はいつも横軸。** 左が過去、右が未来。7日を並べるものは表と同じドラムで動かす（1日だけを見る時間帯は1日ずつ、1か月・1年は全体を見るので動かさない）。
- **時系列のグラフを上下に並べるときは、横軸を共有する（2026-11-18）。** 単位や刻みが違う系列（雨の強さ mm/h の5分ごとと、1時間の降水量 mm など）は1つの軸に重ねず段を分けるが、段どうしの時刻はそろえる。
  - 同じ時刻はいつも同じ横の位置（左右の余白も同じ）。表示の幅（6・12・24時間など）を切り替えるときは、全部の段に同時にかける。
  - 「今」の線・予報の網かけ・選んでいる時刻は、段を通して1本で示す。粒度が違う段では、選んだ時刻を含むその段の区切り（5分なら5分、1時間ならその1時間）を囲む。
  - 時刻の目盛りは一番下に1組だけ。段ごとに繰り返さない。段の名前と単位は各段の左上に書く。
  - 刻みはそろえない：1時間の棒はその1時間の幅で描く（5分に割って描かない）。データの無い区間は空けて「なし」と書く（0 に見せない）。
  - 段のあいだに凡例や見出しを挟まない（挟むと別のグラフに見え、時刻をそろえて読まれない）。凡例は一番下の段の真下に置く。

## 4.2 タップしたときの動き

- **押せる範囲は 44px 以上**（iPhone の指の大きさ）。SVG の中の「選ぶ場所」（グラフの発表・日を選ぶ所など）も同じで、見た目が細くても押せる範囲は別に 44px 取る。`IconButton`（見た目 36px、`sm`・閉じる 32px）は、見た目はそのまま押せる範囲だけを 44px の円に広げる（2026-11-18、見本で決めた。見た目を 44px にすると、見出しの行が太り、隣のボタンやグラフと重なった）。見た目が小さい押す所は、見た目を変えずに押せる範囲だけを `::after` で `TAP.min`（`--tap-min`、44px）まで広げる（`Button sm` と同じやり方）。横に並ぶ隣がある物は縦だけ広げ、広げた範囲が隣の押す所に重なる物は広げない（#296、2026-11-18）。入力欄は高さを 44px にする。チップ（`.chip`、28〜34px）も見た目は変えず、押せる範囲だけを縦に 44px まで広げる（見本で決めた、2026-11-18 案A）。
- **情報を `title` 属性や、ポインタを乗せたときの表示だけに置かない。** スマホでは読めない。空きの理由（値なし・項目なし・記録なし など）や補足は、押せば出る形にする（#260 の外部レビューから）。`title` は、押して読める形と同じ内容を足すときだけ使ってよい。
- 表の列やグラフの日をタップしたら、**別の画面へ移る**（時間帯へ）。戻るには「‹ 日別」を使う。
- マップのマスをタップしたら、**その場で詳しい値が開く**。閉じるには、その詳細の × を押す。
- チップを押すと、表示を切り替える（線を出す・消す、項目を変える）。

## 4.3 比較を読みやすくする決まり

- **差の行：** 比較の表の下に、その項目の主な値の「差（対象−比較）」の行を置く。色は付けない。
- **表に集中：** 表だけを表示するときは9日分にして、数字をひと回り小さくする。
- **固定の1行：** 時間帯の要約は、日付の見出しが隠れたら、1行にしてシートの見出しの下に置く。スクロールする範囲の外なので、内容には重ならない。この1行をタップすると、要約の先頭に戻る。
- **肌感マップ：** 左右にスワイプすると、1日ずつ動く。
- **要約の日付をタップ：** 点線の下線がある日付はタップできる。対象日をタップするとカレンダーが開き、区間はそのままで日が動く。比較日をタップして好きな日を選ぶと、区間がカスタムになる（比較のしかたが「カスタム」になり、連動はそのまま）。固定の1行でも同じ。
- **1行の表示：** 1行にした要約では、日付の前に「対象」「比較」と書く。比較日が別の年のときは '25 のように年を短く書く。
- **引っ張ったときの案内（`SwipeHint`）：** 横に引っ張って日を動かせる面（要約、固定の1行、肌感マップ）では、引っ張って空いた側に移動先の日付と「次の日／前の日」を出す。離せば移動するところまで引くと、アクセント色の「離すと移動」に変わる。

## 4.4 状態の見せ方（読み込み中・遅い・失敗・オフライン）

- **うまくいっているときは何も出さない。**
- **読み込み中：** 値の場所は骨組み（光が流れる灰色の帯）で見せる。グラフは大きさを変えずに、上に「取得中…」を重ねる。後から何かが入って画面がずれることはない。
- **遅いとき：** 選んでいる日が4秒たっても読み込み中なら、項目チップの下の1行に「データの取得に時間がかかっています…」と出す。
- **失敗したとき：** 表のマスは「—」にして、状態の行を赤字の「取得失敗」にする。再試行のボタンは、項目チップの下の1行にまとめて1つだけ置く（「N日分のデータを取得できませんでした。［再試行］」）。グラフは、その場所に理由と［再試行］を出す。
- **オフライン：** 項目チップの下の1行に「オフラインです。保存してあるデータを表示しています。」と出す。通信が戻ったら、失敗したものを自動で取り直す。
- 自動の再試行（少しずつ間隔を空けて取り直す）は、この表示とは別に裏で続ける。

## 4.5 信頼度

- 予報の日には「予報」の後ろに信頼度（A・B・C）を付ける。表の状態の行、要約のバッジ、グラフの凡例で同じ書き方にする。
- 出どころは Open-Meteo のアンサンブル予報（ECMWF IFS の51通り、15日先まで）。同じ予報を少しずつ条件を変えて51回計算し、その結果のばらつきで決める。**アプリ独自の基準で、気象庁の週間予報の信頼度とは別のもの。**
  - 気温：51通りの最高気温・最低気温の標準偏差のうち、大きい方が 1.5℃以下なら A、3℃以下なら B、それより大きければ C。
  - 雨：1mm以上降る計算の割合が 35〜65% なら C、20〜80% なら B（降るか降らないかで計算が割れている）。
  - 気温と雨のうち、低い方の評価をその日の信頼度にする。
- 色は C（注意）にだけ付け、A と B は控えめな色にする。
- アンサンブルが取れなかった日（15日目より先など）には何も付けない。
- 基準の値は `shared/confidence.ts` にまとめてある。

## 4.6 カレンダー

- **一番上に組み合わせを出す：** 「対象 11/10（火） ↔ 比較 11/3（火）」と、その間隔を言葉で書く（前日・前週・前年同曜日・7日前 など）。選んでいる側の日付を明るくする。
- **比較日を選ぶとき：** 組み合わせの下にプリセット（前年同日・前年同曜日・前日・前週・翌週）を並べる。プリセットを選べばその比較のしかたに、日を選べば区間が「カスタム」になる。
- **マス：** 日にち、天気、最高気温を出す。もう一方の側の日には小さく「対象」「比較」と付け、今選んでいる日は枠で囲む。予報の日は網かけ、今日は日にちに下線を引く。信頼度が C の日は「C」を添える。
- **選び方：** タップすると上の組み合わせが変わる（まだ決まらない）。同じ日をもう一度タップするか［決定］を押すと決まり、閉じる。
- **月の移動：** ‹ › か左右のスワイプで1か月ずつ動く。年は見出しの年を押して選ぶ。［今月へ］で今月に戻る。
- **データがないマス：** 読み込み中は、天気と気温の場所が薄く明滅する。取得できなかった日とデータのない日は「—」にする。予報の範囲より先の日は、枠線だけの薄いマスにして選べなくする。月の下に「11/26（木）以降は予報がありません（16日先まで）。」と書き、取得できなかった日があれば［再試行］を添える。空白のままのマスは作らない。
- カレンダーは、表の日付・要約の日付・固定の1行のどこから開いても同じものを使う。

## 4.7 週単位で動かす（◀ ▶ の長押し）

- ◀ ▶ をタップすると1日、**長押しすると1週間**動く。長押ししたまま**下へ引く**と、引いた距離（40px ごと）で2週、3週…と増える。◀ は画面の左端に近いので、縦の動きを基本にする（矢印の向きへ横に引いても同じように増える）。
- 長押しの間は、日付の表示が着地する日（アクセント色）に変わり、見出しの右に「3週後 ↓で増える・↑で取り消し」の札が出る。どちらも指より上にあるので、指で隠れない。
- 上へ戻すと「取り消し」になり、離しても動かない。

## 4.8 設定

- 3つのまとまりに分ける：**地点**（観測地点・風速計の高さ）、**肌感の基準**（7段階の6つの境目・周りの様子・日差しの強さ）、**表示**（肌感（日なた／日かげ）、肌感の段階 7段／5段／3段）。保存データは最後に畳んで置く。
- 肌感の境目は、肌感の行と同じ7色の帯（−5〜40）で見せる。段の名前は幅が足りるところにだけ書き、− ＋ の欄で全ての境目に名前を付ける。帯の上で境目を指で動かすか、− ＋ で0.5ずつ変える。隣の境目とは0.5以上離れる。
- 選択肢が少ないもの（周りの様子・日差しの強さ・日なた／日かげ）は、プルダウンではなく切り替え（`Segmented`）にする。
- 日別グラフの肌感のチップは、押すたびに「肌感（日なた） → 肌感（日かげ） → オフ」と切り替わる。日なた／日かげは表・グラフ・時間帯で共通の設定。

## 4.9 読み上げ（VoiceOver）

- ボタンには、見た目の記号ではなく動作を名前に付ける（「対象日を1日前へ」「対象日 2026/11/11（水）。カレンダーを開く」）。
- カレンダーのマスは「日付・祝日・今日・予報・最高気温（または読み込み中／取得できませんでした／予報の範囲外）・信頼度C・選択中」の順で読む。
- 状態が変わる所（長押し中の週数、カレンダーの組み合わせ、注記）は `aria-live` で知らせる。

## 4.10 β版の表示（最近との差）

- 検証中の指標には、見出しやチップに枠付きの「β」を付ける。肌感（日なた・日かげと7段階）とは別の計算で、別の場所に置く。
- **肌感の中心とちょうどよい範囲（考え方の根本）：** 感じ方は直線ではない。暑くも寒くもない肌感のまわりに「快適」範囲があり、その外に出たところで涼しい・暖かいへ段階的に進む。その中心の位置も範囲の広さも、最近の気温への慣れや湿度・気温の振れで動く。「肌感の中心とちょうどよい範囲 β」の欄（要約の下。見出しを押すと畳める・広げる。初めは畳んでいて、記録と根拠のボタンは畳んでも見える）は、各日の最近の基準・暑くも寒くもない肌感・ちょうどよい範囲・日なた／日かげが中心からどれだけか（範囲内／外ならどれだけ外か）を並べる。要因の組み合わせが違う複数のモデルを並べて当てはめ、証拠の強さで重みを付けて混ぜる（根拠の画面にモデルの比較表）。式と推定は README の 8 章。
- **最近の基準：** 過去の日平均気温の移動平均（EN 16798-1 の θrm）。慣れの速さ α は**本人が選ばない**。感じ方の記録が30件たまったら、肌感の中心とちょうどよい範囲のモデルの当てはまりがいちばんよい α を候補から選ぶ。それまでは規格の標準値 0.8。設定には今の α と、その根拠（記録から選んだ／標準値）、半減期と前日の重み（研究メモの「更新率」＝1−α）を並べて出す。履歴は60日（遅い α でも重みのほぼ全部が入る）。取得中は「読み込み中」、取得できたのに足りないときだけ「履歴不足」と書き、記録のボタンは読み込みが終わるまで押せない。関数の形や要因の比較は research/ で CSV に対して行う。前日の値と、重みの8割以上の過去データがなければ「履歴不足」と書き、推測で埋めない。予報の日を含むときは「予報含む」と添える。
- **差：** その日の平均気温、日中（9〜17時）の肌感（日なた・日かげ）から基準を引いた値（単位なし。肌感は℃にそろえた目盛りなので、気温の基準と引き算できる）。日なた・日かげの差には、風・湿度・日差しがすでに入っている。**体感の予測とは書かない**（係数をまだ推定していないため）。
- **置き場所：** 時間帯の要約の最後に「最近との差 β」としてまとめる（対象・比較・差の3列は他の行と同じ）。気温の日別グラフには、基準を細い線（チップ「最近の基準β」）で描く。

- **感じ方の記録（β②）：** 対象日が今日のとき、「最近との差 β」の見出しに［今の感じ方を記録］を置く。感じ方（寒い・肌寒い・涼しい・暑くも寒くもない・暖かい・少し暑い・暑いの7段階、−3〜+3）、いる場所（日なた／日かげ／半々）、風（強い／弱い／なし）、今の天気（快晴／晴れ／薄曇り／曇り／雨／雪）の4つを選ぶと記録できる。夜（日の入りから日の出まで、モデルの夜と同じ）はいる場所を聞かず、3つで記録できる（日差しがないので日なたも日かげも同じ温度）。観測所のその時刻の値（出どころ付き）、その時刻の予報の天気、肌感（日なた・日かげ）、最近の基準と差、過去60日の日平均気温、直近7日の最高・最低・平均・湿度・日照・日射・降水・天気（出どころ付き）は自動で添える。予報と実際の天気の突き合わせ、前日・1週間の影響の分析（ベイズ回帰による指数）は research/ で行う。ボタンは中立の色にし、肌感の段階の色は使わない。
- **アカウント：** 設定の「表示」の下に「アカウント」を置く。ログイン前はIDとパスワードの欄と［ログイン］だけ（説明は1段落）。ログイン後は「ログイン中」と［ログアウト］、記録の保存（同期の状態1行と［今すぐ同期］）、研究への協力（2択、初めは「協力しない」）、管理者には［ユーザー管理］。β のまとまりはログインしているときだけ出す。グラフの「最近の基準」の線と要約の β の行も同じ。
- **記録の入口：** ログイン中は、ヘッダーの設定の左に［記録］（アクセント色の枠の丸ボタン）。記録すると2.5秒だけ「記録しました」に変わる。通知から開いたときも同じ記録の画面。
- **記録の通知：** 「通知する／しない」の2択、時刻はチップ（×で外す、時刻の欄＋［追加］、最大6つ）、曜日は7つの切り替え。端末の状態は1行（受け取る／受け取っていない／ブロック中／ホーム画面に追加が必要）で、ボタンは状態に合うものだけ（［この端末で受け取る］か［テスト通知］［この端末では受け取らない］）。
- **台風の目安**（#220）：記録の通知とは別の「知らせる／知らせない」（最初は知らせない）と、通知の時間帯（から〜まで、既定 7:00〜22:00）。時間帯の外に見つけた知らせは時間帯が来てから送る。端末がまだ受け取っていなければ［この端末で受け取る］だけ出す。
- **一度だけ見せる秘密（パスワード）：** アクセント色の枠に等幅で大きく出し、［コピー］と「この画面でしか見られません」を添える。
- **ユーザー管理：** シートで開く（設定の上に重ねるので、ページの最上位に描く）。追加、ユーザーの一覧（記録の件数・研究・作成・最後のログイン）、再発行と停止（押すと確認の文言に変わる）、研究用CSV。
- **予測を必ず出す：** 記録の画面には、データからの予測を7段階それぞれの確率の棒で出す（最も確率の高い段階を塗り、本人の答えを枠で示す）。あわせて、その瞬間の暑くも寒くもない肌感・範囲と、その場の肌感が中心からどれだけか（範囲の中か、外ならどれだけ外か）を書く。感じ方を選んでから見せる（先に見せると答えが予測に引っ張られ、学習の元になるずれが歪むため）。予測は**送信した時刻**の観測値・選んだ場所と風で計算し直し、画面を開いた時刻と送信時刻の両方とともに記録に残す。成績（当たり・対数損失・偏り・平均のずれ・直近10件）は設定と根拠の画面に集計する。
- 記録は天気の保存とは別の場所に置き、［保存データを消去］では消えない。設定の「最近との差 β」で件数を見て、CSV に書き出し、消せる（消すときは2回押す）。

- **計算の根拠（研究用 β の約束）：** β の値には必ず根拠の画面を付ける。「最近との差 β」の［根拠］と、設定の α の下の［計算の根拠を見る］から開く。対象日・比較日を切り替えて、次を並べる。
  - 最近の基準：式、α（半減期・前日の重み）、過去の日ごとの日平均・重み・出どころ（確定／暫定／予報／欠け／取得中）、そろっている重みの割合
  - 気温の差：その日の平均気温 − 基準 の引き算と、平均気温の出どころ
  - 日なた・日かげの差：日中・昼・夕方の気温・湿度・風（観測→人の高さ）・日射と、その時間帯の肌感（日なた・日かげ）、使った式と設定値
  - この日の暑くも寒くもない肌感・範囲（95%区間）と入力、日なた／日かげが中心からどれだけか
  - モデルの式と、各要素の初め（固定の事前分布。肌感の表示の境目からは作らない）・今の値・95%区間。要因は区間が 0 をまたげば「まだ分からない」、またがなければ「効いている」
  - α（標準値か、記録から選んだか）と、予測の成績
  - 合計の値は要約と同じ関数で出すので、根拠の画面と要約の数字は必ず一致する

## 4.11 動いている間

- ドラムが動いている間（指が触れている間と、止まるまでの短い間）は、表示する日の並びを変えるスイッチ（連動／個別、比較のしかた）を押せないようにして、薄く表示する。止まればすぐに押せる。
- それでも動いている途中で日の並びが変わったときは、その操作を取りやめて、選んでいる日に戻す（違う日に止まらない）。
- 比較のしかたの表示は、いつも今の組み合わせと一致させる。個別で日を動かして組み合わせがプリセットから外れたら「カスタム」に、プリセットと一致したらその名前にする。連動に戻すときも、プリセットと一致していればその名前のままにする（前日なら前日）。

## 4.12 ボタンと操作の体系（#151）

ボタン単体の美しさではなく、並んだときに「次に何を押すか」が自然に分かることを目指す。

| 役 | 例 | 見た目 |
| --- | --- | --- |
| 進む | 決定・記録する・すべて再試行 | 主（`primary`）：青の塗り、上の縁に光 |
| する | 再試行・同期・今の感じ方を記録・移り変わり | 副（`secondary`）：チップと同じ面と枠、文字は白く太く |
| 補う | 根拠・詳しく・計算の根拠を見る | 控えめ（`quiet`）：青の文字だけ。押している間だけ淡い面 |
| 移る | 戻る・閉じる・日付送り | 決まった位置（戻るは左上、閉じるは右上、送りは日付の両脇） |
| 選ぶ | 項目チップ・切り替え・曜日 | 選んでいるものだけ青の縁と薄塗り |
| 消す | この端末から消す | 危険（`danger`）：赤の枠。`DangerButton` で2回押し |

1. **青の縁・青の薄塗りは「選んでいる」印だけ。** 実行するボタンには使わない（押せるのか選ばれているのかが分からなくなる）。
2. **主は、いちばん上に開いている画面に1つだけ。** 表・グラフ・マップのように見て回る画面には主を置かない。そこでの次の一歩は、日をタップする・スワイプするといった直接の操作。
3. **主は押せるようになった時に青くなる。** それまでは灰色の面で、何が足りないかをボタンに書く。
4. **主は流れの最後。** シートの下に置き、2つ並ぶときは主が右。横いっぱいのボタンは同じ幅。
5. **操作は働く相手のそばに置く。** カレンダーの［今月］は月の送りの横で、下の段は［決定］だけ。
6. 形：行の中は丸、横いっぱいは角の丸い四角（10px）。高さはチップ・小ボタンが 32、ボタン・丸ボタンが 36 で、同じ行では中心で揃う。
7. 状態：押している間は 97% に縮んで色が沈む。キーボード操作の時だけ外側に青い輪。処理中は回る輪を出し、幅は変えない。終わったら ✓ を添える。

見張り：e2e で、表・時間帯・設定は主が 0、カレンダー・取得できなかったものは主が 1、どのボタンも押せる高さが 32 以上。

## 4.12b 強風・暴風の印（#175）

台風や強い低気圧の日が、ただの雨の日と同じに見えないように、天気の絵の肩に小さな丸い札（風の絵）を付ける。

- 基準（`shared/storm.ts`）は気象庁の高知市の注意報・警報の基準：**強風** は最大風速（10分平均の最大）12 m/s 以上か最大瞬間風速 20 m/s 以上、**暴風** は最大風速 20 m/s 以上か最大瞬間風速 30 m/s 以上。
- 入力は実績にも予報にもある値だけ（データの決まり）。天気概況の「暴風を伴う」は実績にしかないので使わない。時間帯の天気の行は、毎時の値が実績には平均風速しかないので、平均風速だけで判定する。
- 色は注意の黄（`status.warning`）。強風は枠、暴風は塗り。表は絵の右上、カレンダーは絵の右（日付の数字に重ねない）。札の読み上げと長押しで理由（最大風速・最大瞬間）を出す。

## 4.12c その日の要約（長押し、#176）

天気の絵を長押しすると、その日の要約が開く。入口は1つの決まりで、天気の絵のある所すべて（表・カレンダー・時間帯のグラフの天気の行）で同じ。タップの動き（日を開く・選ぶ）はそのまま残し、長押しが決まったときだけ後のタップを捨てる。

- 中身の順：まとめ（浮いた面：天気の絵・天気・状態の札と、数字から作った一言）→ その日の値（沈んだ面：グラフの読み取りと同じ表、対象・比較・差。下に時間帯の天気）→ 時間ごと（沈んだ面：気温の小さなグラフ、対象は実線・比較は破線、降水はその日の棒。触っても読まない一目用）→ 強風・暴風の日だけ「風の強さ」（沈んだ面：最大風速・最大瞬間の棒と基準の目盛り、最低気圧）。
- 一言（`src/data/dayComment.ts`）は決まりだけで作り、表にない値は言わない。最大3文、1文ずつ改行：①比較日との最高気温の差（1℃未満は「ほぼ同じ」、3℃以上は「かなり」。寒暖差10℃以上はそれも）②雨か日差しの目立つ方 ③強風・暴風なら、毎時の値で風がいちばん強かった時刻と最大瞬間。予報の日は「見込み」と書く。
- 風の棒は値の項目の色（平均風速・最大瞬間の色）、基準の目盛りは注意の黄（強風・暴風の印と同じ意味）。値の文字は黄にしない。
- 長押しの所は文字の選択・長押しメニューを出さない。

## 4.13 カード（#151）

カードは2種類だけ。面・角・縁・余白は styles.css のカードの規則1か所で決め、個別に書き直さない（`test/ui/tokens.test.ts` が見張る）。

| 種類 | 使う所 | 面・角・縁・余白 |
| --- | --- | --- |
| 浮いた面 | 比較の要約、肌感マップの要約、移り変わりの見出し、カレンダーの組み合わせ、設定のまとまり、条件の一覧・表、その日の要約のまとめ | `surface.raised`＋上の光沢、角 `lg`（14）、縁 `line.soft`、余白 12・16（比較の要約だけ詰める） |
| 沈んだ面 | グラフの読み取り、β の予測、太陽のシート（グラフと時刻）、その日の要約の値・時間ごと・風の強さ | `surface.inset`、角 `md`（10）、縁 `line.soft`、余白 8・16 |

- 浮いた面は「まとめ・結論」、沈んだ面は「数字を読む所」。
- カードの中にカードを入れない。まとまりは見出しの線（`SectionHead`）で区切る。

## 4.13a 1日モード（`DayDetail`、#247）

見出しの右に［比較｜1日］。持つのは「比較日を出すか」だけ（`view.single`、端末に覚える）。1日にすると比較の表・下のシート（日別のグラフ）・差は出さず、対象の7日の表はそのまま、その下に選んだ日の詳しい画面を出す。表の日付を押すとその日に変わる。比較に戻すと前の比較のしかたに戻る（対象日が比較のしかたの範囲の外なら範囲に戻す）。

- 並びは「どんな日か → いつ → 何が → 根拠」：一番上（天気の絵・最高／最低・実績か予報か＋信頼度・一言）／① 1日の流れ（日の出・日の入り・昼の長さ、時間帯の5つ、選んだ項目の24時間＝時間帯のシートと同じグラフ）（24時間の見出しのすぐ下に、値つきの項目の選び 4列×2段。押すとすぐ下のグラフがその項目になり、上のタブも変わる。選んだ項目の残りの値はその下の1行）／② 根拠と記録（その日の自分の記録、予報の移り変わり、それと連動する天気図［発表の時｜この日］、その日の要約への入り口）。肌感は一番上の右（押すと肌感マップ）。出どころは一番上の ⓘ。雨の見込みは今日だけ（札＋「直近の雨雲レーダー」でシート）（2026-11-18 #313〜#319）。
- 時間帯は太陽で決まる5つ（朝・日中・昼・夕方・夜）。押すとその時間帯の1時間ごと（天気・気温・降水・降水確率・風速・肌感）が開く。
- 空の色は①に重ねない：今の日照・時間帯のグラフの下の「太陽」の帯に任せる。
- 新しく計算するものはない：値・時間・時間帯・一言は比較の画面と同じもの（`chartMetrics`・`dayDetail`・`dayParts`・`dayComment`）。読み取りカードは1日だけのとき比較と差の列を出さない（`GraphReadout single`）。

## 4.13b 近づいている台風（`TyphoonCard`、#220）

台風が観測点にかかわるときだけ（強風域・暴風域に入っている、暴風警戒域に入っている、中心が 1000km 以内）、ヘッダーの下に浮いた面で出す。

- 中身はすべて気象庁の発表のまま（台風◯号・名前・中心気圧・位置・進む向きと速さ・最大風速）。**予報を動かしたり補ったりしない**（自前の予報は気象業務法の許可が要る）。観測点が気象庁の円（強風域・暴風域・暴風警戒域）の中にあるかを見るだけ。
- 域の中にいるときは縁を警告の色に、「強風域に入っています」を警告の色で。外のときは中心までのおよその距離。
- 「前の台風の日と比べる」で条件から選ぶを開く：台風の日・気温と雨は問わない・過去5年・通年（台風は季節に偏るので前後1か月では空になりやすい）。台風の日だけのときは、その日だけを読む。
- 出典「気象庁『台風情報』（◯日◯時発表）」と「域に入っているかは Weather Note の判定」、気象庁の台風情報へのリンク。
- 取れなかったとき（JSON の形が変わった、つながらない）は「台風情報を取得できませんでした」と一行出す（台風なしと区別する）。前に取れた情報があれば、それを「◯時◯分の情報です（そのあと更新できていません）」と添えて出す。
- 「接近」は分けて書く：暴風域に入っています／強風域に入っています／暴風警戒域に入っています（予報）／域の外（中心から約◯km）。
- ベストトラックは季節の後に追加される（2026年11月時点で8月24日まで）。その翌日から先は、残した電文（当時の発表）の実況・推定で同じように出す（`shared/typhoonRecent.ts`、`/api/typhoon-recent`）。どちらも届かない日（2026年は 8/25〜11/8、電文を残し始める前）は「台風の日なし」ではなく「まだ記録に入っていない」と書く（月の振り返り・条件から選ぶ・表）。電文の日を含むときは出典に「当時の発表＝防災情報XML」を添える。台風がベストトラックに入れば、その台風はベストトラックだけで出す。
- **表の「台」**：天気の絵の左肩に、その日に観測点が台風の域に入った印。過去の日はベストトラック（強風域は枠・暴風域は塗り）、今日から先は気象庁の今の発表（強風域・暴風域は同じ、暴風警戒域は破線）。右肩の強風・暴風の印（観測の風）とは別の意味なので並べて置く。

## 4.14 月の振り返り（`MonthReview`）

カレンダーの月の名前（点線の下線）を押すと開く。1か月を、**前年同曜日**（52週前、土曜は土曜と）と比べて振り返る。値は記録だけ。今月は今日まで。

- **絞り込みは1か所。** 上の2段だけで選び、どのページもそれに従う。
  - 時間：1日／朝／日中／昼／夕方／夜（複数可）。時間帯を選ぶと、気温・雨・日照・湿度・風・気圧をすべてその時間帯の毎時の値から作る（1日の値と混ぜない）。
  - 日：全／月〜日（複数可）。曜日の並びを**下に引くと**その場でカレンダーになり（つまみを押しても開く）、日・週・曜日で選べる。たたむのはつまみを上へ（カレンダーの上で上に引くとスクロールとぶつかるため）。開いている間は上の曜日の並びを隠す（同じ選び方を2つ並べない）。「日付」「閉じる」のボタンは置かない。
  - 選んだ日は「選んだ N日 ×」で示し、× で月全体に戻る。グラフ・カレンダー・曜日の行は月全体のまま、選んだ日を枠で示す（塗らない）。
- **ページは4つ**（`Segmented`）：まとめ（月の値・レポート）／日ごと（項目を選んでなぞる）／曜日（曜日の傾向）／肌感（時間帯ごとの月）。選ぶ所はページの中に置かない（曜日の行は押しても選ばない）。
- **レポートは選んだ日に合わせる。** 上旬・中旬・下旬は日付で分け、「〇日続いた」は日付が続く範囲だけで数える。中身は 気温／雨と日差し／目立った日（強風・暴風の日を含む）／日の出・日の入り。日の出入りは日付と場所からの計算値と書く（記録ではない）。曜日と肌感はそれぞれのページに任せ、レポートに重ねない。
- **棒は塗り（この月）と枠（前年同曜日）。** 曜日の行は、太い塗りの棒の下に細い枠の棒。量の棒は 0 の端を四角く、値の端だけ少し丸める。曜日を2組まとめて比べる段は、曜日を自由に入れられる（平日／土日で固定しない）。
- **台風の日**（#220）：気象庁のベストトラック（`public/data/typhoon-tracks.json`、ワークフロー typhoon-tracks が月1回作る）から、その日に観測点が台風の強風域・暴風域に入ったかを出す。形は気象庁の図と同じ「ずらした円」（`shared/typhoon.ts`）。
  - カレンダー：日の右上に「台」。強風域は枠、暴風域は塗り（表の強風・暴風の印と同じ見せ方）。
  - レポート：「台風」の項目に、台風◯号・入った日・域・いちばん近い距離と気圧、前年同曜日の台風。強風・暴風の日には「うち台風 ○日」。
  - 出典「気象庁（ベストトラック）」と「強風域・暴風域に入ったかは Weather Note の判定」を必ず添える（気象庁の利用条件：加工したら加工したことと責任を書く）。
  - データが読めないときは台風を出さないだけで、画面は止めない。
- **当時の発表を残す**（#220、まだ画面には出さない）：気象庁の防災情報XML（台風解析・予報情報 VPTW6x）を、定時の処理（5分ごと）で取り、そのまま D1 に残す（`worker/src/typhoonArchive.ts`、読み方は `shared/typhoonXml.ts`）。
  - 電文そのもの（XML）・その読み（読み方の版つき）・気象庁の発表時刻・取った時刻を分けて持つ。残したものは書き換えない。
  - 取りに行った回はすべて記録する。台風の電文がなかった回も「なかった」という結果として残し、取れなかった回は欠け（gap）として残す。空のフィードは「台風なし」ではなく欠け。
  - 短いフィード（約10時間）を毎回読み、初回と8時間を超えて取れなかった後は長いフィード（7日）で追いつく。管理者は `/api/admin/typhoon-archive` で残ったものと欠けを見られる。
- **台風の詳細**（#220、`src/ui/TyphoonSheet.tsx`・`shared/typhoonMap.ts`）：台風の日の「その日の要約」から開く（絵の横に台、一言の最初に「台風◯号の強風域に入った日。」、その下に入り口）。台はカレンダー・比較の要約の絵の横にも出す（`TyphoonTag`、表と同じ見え方）。
  - 地図は自前の線画：Natural Earth（1:10m、パブリックドメイン）を日本周辺で切った `public/data/coast-japan.json`（`scripts/coast.ts`）を、観測点を中心に km で描く。外の地図サービスは使わない。＋−で寄れる。
  - 見るものは3つ：実際（進路と、選んだ時刻の強風域・暴風域＝ずらした円）／当時の予報（残した電文の予報円・暴風警戒域を気象庁の発表のまま。2026年11月より前の台風は「残っていません」）／今（台風のカードと同じ気象庁の今の発表）。
  - 地図の下に観測点にとっての帯：発表ごとに暴風警戒域に入った時間（言うことが変わった発表と最新だけ）、最後に実際（強風域・暴風域に入った時間）。
- **止まったら知らせる**（#220、`worker/src/typhoonWatch.ts`）：定時の処理が台風の情報元を見張り、管理者の端末に通知する（始まったときに1回、戻ったときに1回。同じことは繰り返さない）。
  - 電文の収集が60分読めない／残した電文が読みきれない（電文ごとに1回）／今の台風情報（JSON）が3回続けて読めない／電文にある台風（6時間以内・終わっていない）が直後の JSON にない（形が変わった疑い）。
  - 知らせたことは `typhoon_alerts` に残し、`/api/admin/typhoon-archive` に出す。定時の処理そのものが止まったことは中からは分からないので、同じ画面の「最後に動いた時刻」で見る。
- **台風の目安の通知**（#220、`worker/src/typhoonNotify.ts`）：設定の観測地点（端末で選んでいる地点を、入れたとき・変えたときにサーバーへ送る）を、定時の処理（電文を集めた直後）で最新の発表に当てる。
  - 知らせるのは1つの台風で2回まで：① 観測地点が暴風警戒域に入る予報になった（その台風で初めて）② 解析で強風域（暴風域）に入った（初めて）。見つけたらすぐ残し（`typhoon_notify_log`）、送るのは利用者の通知の時間帯の中だけ。
  - 時間帯が来たとき、①は最新の発表でまだ予報されていれば送り（時刻は最新の発表のもの）、もう予報されていなければ送らない。②は見つけてから12時間を過ぎたら送らない。送らなかったものも記録に残す（devices = -1）。
  - 言い方は「Weather Note の目安です。警報・注意報は気象庁の発表で確かめてください。」を必ず添え、「警報」「避難」を通知の題に使わない。押すと台風の詳細シートが開く（`/?typhoon=<番号>`、開いているアプリにはメッセージで）。
- **昼の長さ**（日ごと）：前年同曜日は暦が1日ずれるだけで線が重なるので、前年の線は描かない（読み取りカードには出す）。
- カードの中に箱を作らない。まとまりは細い線で区切る。

## 5. 閉じ方・戻り方

**オーバーレイのシート（肌感マップ・似た日・カレンダー・設定・雨の見込み・天気図を大きく）はすべて同じ閉じ方にする。閉じたら、開く前の画面の位置に戻る（4.0）。**

1. 上端のグラバー（つまみ）を下へドラッグ（速く弾いても閉じる）
2. 見出しの右端の ×
3. 背景（暗くなった部分）をタップ
4. Esc キー

- 下部の「閉じる」ボタンは置かない。
- 選ぶシート（似た日・カレンダー）は、選んだら閉じる。
- 「‹ 日別」は**シートの中で前の画面に戻る**ためのもの。閉じるのには使わない。
- グラフのシートは閉じない。高さを変えるだけ（最小／中／最大）。最大まで上げたときは項目チップの下で止まる。
- **高さ：** 画面として見るオーバーレイ（肌感マップ・似た日・設定）は、グラフのシートを最大まで上げたときと同じ高さで開く（`size="full"`）。カレンダーのような短い選択は、中身の高さで開く（`size="fit"`）。

## 7. 動き（`MOTION`）

| トークン | 時間 | 用途 |
| --- | --- | --- |
| `quick` | 140ms | 押したときの反応（縮む、色が変わる） |
| `base` | 220ms | 切り替え、帯の移動、ピンの出入り |
| `enter` / `exit` | 380 / 260ms | オーバーレイの開閉（閉じる方を短く） |
| `settleMin–Max` | 220–460ms | 指を離した後にシートが止まるまで（距離と速度で決める） |

- イージング：`standard` は一般の動き、`sheet`（iOS のシートに近い減速）はシート、`exit` は閉じるとき。
- シートの物理：速度は直近 100ms から測る。弾く速さが 0.4px/ms を超えたら、少なくとも1段は動かす。端では輪ゴムのように抵抗をかけ、指を離すと戻す。
- グラバーは指が触れている間、幅を広げて明るくし、触れていることを伝える。
- `prefers-reduced-motion` のときはアニメーションを止める。

## 8. 効果

- 背景を暗くする：グラフシート `effect.scrim`＋ぼかし 2px、オーバーレイ `effect.backdrop`＋ぼかし 4px。
- 浮いたものの影：カード `shadow.card` → シート `shadow.sheet` → オーバーレイ `shadow.overlay`。固定表示の行は `shadow.pinned` と `effect.blur` で、すりガラスのように見せる。
- 面の上端にだけ、ごく薄く明るいグラデーションを入れる（光が上から当たっているように見せる）：`effect.gloss`、選んでいる操作は `effect.glossStrong`。
- 面から少し浮かせる（選んだ切り替え・マス・つまみ）：`shadow.lift`。内容の上に浮かぶカード（拡大カード・知らせ）：`shadow.float`。固定した列の端：`shadow.edge`。
- テーマの線と光でできた影（3テーマ共通の形、色はテーマから）：選んでいる・触っている物のまわりの光 `shadow.glow`（14px。12px と混ざっていたのをそろえた、2026-11-18）、主なボタンの立体 `shadow.bevel` と押した時 `shadow.pressed`、見本の上端の光 `shadow.swatchTop`、固定した列の境の線 `shadow.rule`。
- グラフの夜と薄明の時間：網かけはしない。時間帯のグラフの下の「太陽」の帯（その日の空の色、模式）で示す（#151）。
- 色の見本の縁（隣の色と分ける明るい線）：`line.swatch`。色の帯の暗い縁：`line.shade`。
- 角の丸み：`radius.tick`（2、見本・棒・札などの小さい印）／`xs` 4／`sm` 6／`md` 10（カード）／`lg` 14／`xl` 20（シート）／`pill`。円は `50%`。グラフの「選んだ日」の枠（`chart-center`）は `md` 10、予報の移り変わりの「選んだ発表」の枠は `xs` 4、そのマスは `tick` 2（2026-11-18、見本で決めた。以前は 8・3・1.5）。両端が丸い棒は、幅の半分を角にする（数値で書かない）。
- **styles.css と画面のコードに色を書かない。** 透かしの色は `color-mix(in srgb, var(--accent-base) 8%, transparent)` のように、トークンを薄めて作る。見張り：`test/ui/tokens.test.ts`（色・角・重なり順）。
- 中央の帯：連動中は実線＋にじみ、個別のときは破線でにじみなし。

## 8.1 直書きの見張り（#142）

値はトークンから取る。数字や色を直接書いた所は、`test/ui/hardcode.test.ts` が種類と値ごとに数え、`test/ui/hardcode-budget.json`（例外の一覧）と**ぴったり**同じであることを確かめる。

- **増えたら落ちる。** トークンを使うか、理由があるなら同じ PR で一覧に載せる（PR に理由を書く）。
- **減ったら一覧も下げる。** 減ったまま一覧を残すと落ちる（一覧はいつも本当の数）。`HARDCODE_WRITE=1 npx vitest run test/ui/hardcode.test.ts` で書き直す。`HARDCODE_CSV=<ファイル>` を付けると、どこにあるかの一覧も書き出す（2026-11-17 の棚卸しは `docs/audit/hardcode-2026-11-17.csv`）。
- 見張る種類：余白（段の値／段にない値）・線の太さ（枠・輪・`stroke-width`・`strokeWidth`・破線）・影（トークンの外）・時間（段の値／段にない値／動きの曲線／操作の時間）・透かし（`opacity`・混ぜる割合）・コードの角の丸み。コードの文字の大きさは一覧を持たず、0 でなければ落ちる（SVG の中は `TYPE_SIZE` を使う）。
- 色・CSS の文字の大きさ・角の丸み・重なり順は、これまでどおり `test/ui/tokens.test.ts` が例外なしで見張る。
- `src/design/`（トークンそのもの）は数えない。
- 見た目を変えない置き換えは、前と後の「計算された見た目」を比べて確かめる：`WN_STYLES=<ファイル> WN_THEME=<テーマ> python3 e2e/e2e.py <幅>` を前と後で走らせ、`python3 e2e/style_diff.py 前 後 [前をもう一度]` で比べる（3つ目は、走らせるたびに揺れる値を除くため）。

## 9. 言葉

- 肌感は温度ではなく指数（肌感指数、D18）：「肌感（日なた）」「肌感（日かげ）」と書き、数字に℃をつけない。β の中心は「暑くも寒くもない肌感」。気温と「最近の基準」は本物の温度なので℃をつける。
- 対象日／比較日、日別／時間帯、日差し（日射量）と日照（項目名は「日照時間と明るさ」、ボタンは「日照」）、肌感（日なた／日かげ）、寒暖差（最高−最低）。
- 推定値には「目安」、予報には「予報」、まだ確定していない実績には「暫定」と付ける。
- ボタンの文字は動詞か名詞の短い形にする（「表に集中」「選択中の月へ」）。「〜します」は付けない。
