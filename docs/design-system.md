# Weather Note デザインシステム

見た目と操作のルール。値は `src/design/tokens.ts` が唯一の出どころで、`applyTokens()` が CSS 変数（`--surface-*` など）として配ります。
`styles.css` に生の色・時間・z-index を書かないこと。

## 1. 原則

- **比較が主役。** 対象日と比較日は、いつも同じ並びにする（左／上が対象日、右／下が比較日）。どちらかを強く見せるときは、比較日を少し控えめにする（不透明度 0.7〜0.82）。
- **シンプルに、でも豊かに。** 装飾は足さない。奥行きは、ごく薄いグラデーション、柔らかい影、アクセントのにじみ（中央の帯）だけで出す。
- **1つの意味には1つの見た目。** 色、線種、閉じ方、単位の書き方は全画面で同じにする。

## 2. 色

| 役割 | トークン | 使う場所 |
| --- | --- | --- |
| 面 | `surface.page / base / raised / overlay / inset` | 背景 → カード → 浮いたシート → 入力欄やへこんだ面 |
| 文字 | `ink.primary / secondary / tertiary / disabled / onAccent` | 本文 → 補足 → ラベル・単位（補足と同じ明るさ。暗い背景で読みやすさを優先：比較ページで 3 を選択）→ 欠測 → アクセント上の文字 |
| 線 | `line.soft / strong / focus` | 区切り → 枠 → フォーカス |
| アクセント | `accent.base / strong / wash / glow` | 選択中（チップ・帯・カレンダー）だけ |

**データの色（DATA）は 1色につき意味が1つ。**

| 色 | 意味 |
| --- | --- |
| `hot` | 最高（気温・気圧の最高も） |
| `cold` | 最低 |
| `mean` | 平均・気温（参考線） |
| `rain` / `snow` | 降水量 / 降雪 |
| `sun` | 日差し（日射量）、日照（日照時間と明るさ） |
| `humidity` / `wind` / `pressure` | 湿度 / 風速 / 気圧 |
| `feel` | 日なた温度・日かげ温度 |

- 対象日と比較日は**色で分けない**。線は実線（対象日）と破線（比較日）、棒は塗り（対象日）と枠線（比較日）で分ける。
- **線の種類は「どちらの日か」だけを表す。** 予報かどうかで線の種類は変えない。予報の日や時間は、グラフの背景を網かけにし、その上端に「予報」と書いて示す。
- 肌感の7段階は `FEEL_LEVELS`（7色）を使い、5段・3段の簡易表示は `FEEL_SCALE_COLORS[5]`／`[3]` を使う。どれも「段階の目盛り」なので、マスや背景の塗りにだけ使い、線には使わない。色と名前は `levelColor`／`levelName`／`legendOf`（`FeelBar.tsx`）から取り、段数ごとに書き分けない。
- 段階の名前は短くする（チップやマスに収まる長さ）。7段は 極寒／寒い／涼しい／ちょうどよい／暖かい／暑い／猛暑（感じ方の記録と同じ言葉）。5段は 寒い／涼しい／ちょうどよい／暖かい／暑い、3段は 寒い側／ちょうどよい／暑い側。
- 時間区分（朝・日中・昼・夕方・夜）の線は `BAND_LINES`（明るさの違うグレー系）と `BAND_MARKS`（●■▲◆○）を使う。データ色や段階の色とは重ねない。
- **差（+3、−2）には色を付けない。** 赤と青は「最高／最低」の意味なので、「暖かい／寒い」の意味には使わない。大きな差（3以上）は太字で目立たせる。
- 土曜は `day.saturday`、日曜・祝日は `day.holiday`。日付と曜日にだけ使う。
- 状態の色：予報 `status.forecast`、暫定 `status.provisional`、エラー `status.error`。

## 3. 数値・単位・日付（`src/design/format.ts`）

- 単位は数値の後ろに小さく付ける（`.unit`）：℃、mm、cm、%、m/s、hPa、MJ/㎡、h。
- 小数点以下の桁数は単位で決まる：℃ 1、mm 1、cm 1、% 0、m/s 1、hPa 0、MJ/㎡ 1（1時間ごとの値だけ 2）、h 1。1時間ごとの日照は「40分」と書く。
- 差は `signedDiff`：「+1.2」「−0.4」「±0」。マイナスは全角の「−」。どちらかの値がなければ空にする。
- 欠測は「—」（`ink.disabled`）。
- 日付は0で埋めない：「11/9（月）」。年を付けるのは、比較日が対象日と別の年のときと、見出しだけ。
- 軸の目盛りは `niceTicks(lo, hi, 5)` を使って、4〜6本の切りのいい値にする（5 / 10 / 15 / 20）。どのグラフも同じにする。単位は軸の上に書く。

## 4. 部品（`src/ui/kit.tsx`）

| 部品 | 用途 | ルール |
| --- | --- | --- |
| `Chip` | 項目や線を選ぶ | オフは控えめ、オンは `--chip-tone`（線の色やアクセント）で光らせる。`sm` は見出しの中で使う |
| `Segmented` | 表示の切り替え（2〜3択） | 選んだ方を一段持ち上げて明るくする。選んだ方をもう一度タップしたときの動き（`onReselect`）は、日なた／日かげの切り替えだけに使う |
| `IconButton` | ⚙ ⤢ × | 押せる範囲は 36px（`sm` は 32px） |
| `Badge` | 今日／昨日／明日、予報／暫定／実績 | 今日などは塗り、状態は枠線 |
| `DayLabel` | 日付 | 曜日に土曜・祝日の色を付ける |
| `Num` | 数値＋単位 | 丸みのある等幅数字 |

アイコンは `src/ui/icons.tsx` の SVG だけを使う（文字の記号は使わない）。

## 4.1 グラフの共通ルール

- **背景は予報だけ。** 予報の日や時間は網かけにし、上端に「予報」と書く。選んでいる日は背景を塗らずに枠で囲む（表の中央の枠と同じ意味）。
  - 網かけの線は「予報」の文字と同じ青（`status.forecast`）を薄くしたもの（線 24%・地 4%）。グラフ・カレンダー・凡例の見本で同じ色を使う（比較ページで E を選択）。
- **読み取りカード（`GraphReadout`）。** グラフの真上に置き、「何の値か・対象・比較・差」を同じ列で示す。指を離している間は、選んでいる日（または時刻）の値を出す。
- **触っている所に補助線（`GuideLines`）。** 指の位置に縦線を引き、対象日の点から値の軸まで点線を引く。点線が軸に当たる所には、線と同じ色のタグで値を出す。タグ同士が近いときは、重ならないように上下にずらす。触っている間は、読み取りカードの枠が光る。
  - 時間帯と推移のグラフは、触れたらすぐ補助線が出る。
  - 日別のグラフは横スワイプで日を動かすので、長押し（0.28秒）すると補助線が出て、そのまま指を動かせる。マウスでは、ポインタを乗せるだけで出る。
  - 長押しで iPhone の拡大鏡やコピーのメニューが出ないよう、アプリ全体で文字の選択と長押しメニューを止めている（入力欄だけは除く）。
- **凡例はグラフ（マップ）の真下に置く。** 文章ではなく、グラフと同じ見本（線・塗り・網かけ）で示す。肌感の段階の色は、肌感の画面の一番下にまとめる。

## 4.2 タップしたときの動き

- 表の列やグラフの日をタップしたら、**別の画面へ移る**（時間帯へ）。戻るには「‹ 日別」を使う。
- マップのマスをタップしたら、**その場で詳しい値が開く**。閉じるには、その詳細の × を押す。
- チップを押すと、表示を切り替える（線を出す・消す、項目を変える）。

## 4.3 比較を読みやすくする決まり

- **差の行：** 比較の表の下に、その項目の主な値の「差（対象−比較）」の行を置く。色は付けない。
- **表に集中：** 表だけを表示するときは9日分にして、数字をひと回り小さくする。
- **固定の1行：** 時間帯の要約は、日付の見出しが隠れたら、1行にしてシートの見出しの下に置く。スクロールする範囲の外なので、内容には重ならない。この1行をタップすると、要約の先頭に戻る。
- **肌感マップ：** 左右にスワイプすると、1日ずつ動く。
- **要約の日付をタップ：** 点線の下線がある日付はタップできる。対象日をタップするとカレンダーが開き、区間はそのままで日が動く。比較日をタップして好きな日を選ぶと、区間がカスタムになる（比較のしかたが「カスタム」になり、連動はそのまま）。固定の1行でも同じ。
- **1行の表示：** 1行にした要約では、日付の前に「対象」「比較」と書く。比較日が別の年のときは '25 のように年を短く書く。
- **引っ張ったときの案内（`SwipeHint`）：** 横に引っ張って日を動かせる面（要約、固定の1行、肌感マップ）では、引っ張って空いた側に移動先の日付と「次の日／前の日」を出す。離せば移動するところまで引くと、アクセント色の「離すと移動」に変わる。

## 4.4 状態の見せ方（読み込み中・遅い・失敗・オフライン）

- **うまくいっているときは何も出さない。**
- **読み込み中：** 値の場所は骨組み（光が流れる灰色の帯）で見せる。グラフは大きさを変えずに、上に「取得中…」を重ねる。後から何かが入って画面がずれることはない。
- **遅いとき：** 選んでいる日が4秒たっても読み込み中なら、項目チップの下の1行に「データの取得に時間がかかっています…」と出す。
- **失敗したとき：** 表のマスは「—」にして、状態の行を赤字の「取得失敗」にする。再試行のボタンは、項目チップの下の1行にまとめて1つだけ置く（「N日分のデータを取得できませんでした。［再試行］」）。グラフは、その場所に理由と［再試行］を出す。
- **オフライン：** 項目チップの下の1行に「オフラインです。保存してあるデータを表示しています。」と出す。通信が戻ったら、失敗したものを自動で取り直す。
- 自動の再試行（少しずつ間隔を空けて取り直す）は、この表示とは別に裏で続ける。

## 4.5 信頼度

- 予報の日には「予報」の後ろに信頼度（A・B・C）を付ける。表の状態の行、要約のバッジ、グラフの凡例で同じ書き方にする。
- 出どころは Open-Meteo のアンサンブル予報（ECMWF IFS の51通り、15日先まで）。同じ予報を少しずつ条件を変えて51回計算し、その結果のばらつきで決める。**アプリ独自の基準で、気象庁の週間予報の信頼度とは別のもの。**
  - 気温：51通りの最高気温・最低気温の標準偏差のうち、大きい方が 1.5℃以下なら A、3℃以下なら B、それより大きければ C。
  - 雨：1mm以上降る計算の割合が 35〜65% なら C、20〜80% なら B（降るか降らないかで計算が割れている）。
  - 気温と雨のうち、低い方の評価をその日の信頼度にする。
- 色は C（注意）にだけ付け、A と B は控えめな色にする。
- アンサンブルが取れなかった日（15日目より先など）には何も付けない。
- 基準の値は `shared/confidence.ts` にまとめてある。

## 4.6 カレンダー

- **一番上に組み合わせを出す：** 「対象 11/10（火） ↔ 比較 11/3（火）」と、その間隔を言葉で書く（前日・前週・前年同曜日・7日前 など）。選んでいる側の日付を明るくする。
- **比較日を選ぶとき：** 組み合わせの下にプリセット（前年同日・前年同曜日・前日・前週・翌週）を並べる。プリセットを選べばその比較のしかたに、日を選べば区間が「カスタム」になる。
- **マス：** 日にち、天気、最高気温を出す。もう一方の側の日には小さく「対象」「比較」と付け、今選んでいる日は枠で囲む。予報の日は網かけ、今日は日にちに下線を引く。信頼度が C の日は「C」を添える。
- **選び方：** タップすると上の組み合わせが変わる（まだ決まらない）。同じ日をもう一度タップするか［決定］を押すと決まり、閉じる。
- **月の移動：** ‹ › か左右のスワイプで1か月ずつ動く。年は見出しの年を押して選ぶ。［今月へ］で今月に戻る。
- **データがないマス：** 読み込み中は、天気と気温の場所が薄く明滅する。取得できなかった日とデータのない日は「—」にする。予報の範囲より先の日は、枠線だけの薄いマスにして選べなくする。月の下に「11/26（木）以降は予報がありません（16日先まで）。」と書き、取得できなかった日があれば［再試行］を添える。空白のままのマスは作らない。
- カレンダーは、表の日付・要約の日付・固定の1行のどこから開いても同じものを使う。

## 4.7 週単位で動かす（◀ ▶ の長押し）

- ◀ ▶ をタップすると1日、**長押しすると1週間**動く。長押ししたまま**下へ引く**と、引いた距離（40px ごと）で2週、3週…と増える。◀ は画面の左端に近いので、縦の動きを基本にする（矢印の向きへ横に引いても同じように増える）。
- 長押しの間は、日付の表示が着地する日（アクセント色）に変わり、見出しの右に「3週後 ↓で増える・↑で取り消し」の札が出る。どちらも指より上にあるので、指で隠れない。
- 上へ戻すと「取り消し」になり、離しても動かない。

## 4.8 設定

- 3つのまとまりに分ける：**地点**（観測地点・風速計の高さ）、**肌感の基準**（7段階の6つの境目・周りの様子・日差しの強さ）、**表示**（日なた温度／日かげ温度、肌感の段階 7段／5段／3段）。保存データは最後に畳んで置く。
- 肌感の境目は、肌感の行と同じ7色の帯（−5〜40℃）で見せる。段の名前は幅が足りるところにだけ書き、− ＋ の欄で全ての境目に名前を付ける。帯の上で境目を指で動かすか、− ＋ で0.5℃ずつ変える。隣の境目とは0.5℃以上離れる。
- 選択肢が少ないもの（周りの様子・日差しの強さ・日なた／日かげ）は、プルダウンではなく切り替え（`Segmented`）にする。
- 日別グラフの肌感のチップは、押すたびに「日なた温度 → 日かげ温度 → オフ」と切り替わる。日なた／日かげは表・グラフ・時間帯で共通の設定。

## 4.9 読み上げ（VoiceOver）

- ボタンには、見た目の記号ではなく動作を名前に付ける（「対象日を1日前へ」「対象日 2026/11/11（水）。カレンダーを開く」）。
- カレンダーのマスは「日付・祝日・今日・予報・最高気温（または読み込み中／取得できませんでした／予報の範囲外）・信頼度C・選択中」の順で読む。
- 状態が変わる所（長押し中の週数、カレンダーの組み合わせ、注記）は `aria-live` で知らせる。

## 4.10 β版の表示（最近との差）

- 検証中の指標には、見出しやチップに枠付きの「β」を付ける。肌感（日なた温度・日かげ温度と7段階）とは別の計算で、別の場所に置く。
- **ちょうどよい温度と範囲（考え方の根本）：** 感じ方は直線ではない。ちょうどよい温度のまわりに「快適」範囲があり、その外に出たところで涼しい・暖かいへ段階的に進む。その中心の位置も範囲の広さも、最近の気温への慣れや湿度・気温の振れで動く。「ちょうどよい温度と範囲 β」の欄は、各日の最近の基準・ちょうどよい温度・ちょうどよい範囲・日なた／日かげが中心から何℃か（範囲内／外ならどれだけ外か）を並べる。要因の組み合わせが違う複数のモデルを並べて当てはめ、証拠の強さで重みを付けて混ぜる（根拠の画面にモデルの比較表）。式と推定は README の 8 章。
- **最近の基準：** 過去の日平均気温の移動平均（EN 16798-1 の θrm）。慣れの速さ α は**本人が選ばない**。感じ方の記録が30件たまったら、ちょうどよい温度と範囲のモデルの当てはまりがいちばんよい α を候補から選ぶ。それまでは規格の標準値 0.8。設定には今の α と、その根拠（記録から選んだ／標準値）、半減期と前日の重み（研究メモの「更新率」＝1−α）を並べて出す。履歴は60日（遅い α でも重みのほぼ全部が入る）。取得中は「読み込み中」、取得できたのに足りないときだけ「履歴不足」と書き、記録のボタンは読み込みが終わるまで押せない。関数の形や要因の比較は research/ で CSV に対して行う。前日の値と、重みの8割以上の過去データがなければ「履歴不足」と書き、推測で埋めない。予報の日を含むときは「予報含む」と添える。
- **差：** その日の平均気温、日中（9〜17時）の日なた温度・日かげ温度から基準を引いた値（℃）。日なた・日かげの差には、風・湿度・日差しがすでに入っている。**体感の予測とは書かない**（係数をまだ推定していないため）。
- **置き場所：** 時間帯の要約の最後に「最近との差 β」としてまとめる（対象・比較・差の3列は他の行と同じ）。気温の日別グラフには、基準を細い線（チップ「最近の基準β」）で描く。

- **感じ方の記録（β②）：** 対象日が今日のとき、「最近との差 β」の見出しに［今の感じ方を記録］を置く。感じ方（極寒・寒い・涼しい・ちょうどよい・暖かい・暑い・猛暑の7段階、ASHRAE 55 の −3〜+3）、いる場所（日なた／日かげ／半々）、風（強い／弱い／なし）、今の天気（快晴／晴れ／薄曇り／曇り／雨／雪）の4つを選ぶと記録できる。夜（日の入りから日の出まで、モデルの夜と同じ）はいる場所を聞かず、3つで記録できる（日差しがないので日なたも日かげも同じ温度）。観測所のその時刻の値（出どころ付き）、その時刻の予報の天気、日なた温度・日かげ温度、最近の基準と差、過去60日の日平均気温、直近7日の最高・最低・平均・湿度・日照・日射・降水・天気（出どころ付き）は自動で添える。予報と実際の天気の突き合わせ、前日・1週間の影響の分析（ベイズ回帰による指数）は research/ で行う。ボタンは中立の色にし、肌感の段階の色は使わない。
- **アカウント：** 設定の「表示」の下に「アカウント」を置く。ログイン前はIDとパスワードの欄と［ログイン］だけ（説明は1段落）。ログイン後は「ログイン中」と［ログアウト］、記録の保存（同期の状態1行と［今すぐ同期］）、研究への協力（2択、初めは「協力しない」）、管理者には［ユーザー管理］。β のまとまりはログインしているときだけ出す。グラフの「最近の基準」の線と要約の β の行も同じ。
- **記録の入口：** ログイン中は、ヘッダーの設定の左に［記録］（アクセント色の枠の丸ボタン）。記録すると2.5秒だけ「記録しました」に変わる。通知から開いたときも同じ記録の画面。
- **記録の通知：** 「通知する／しない」の2択、時刻はチップ（×で外す、時刻の欄＋［追加］、最大6つ）、曜日は7つの切り替え。端末の状態は1行（受け取る／受け取っていない／ブロック中／ホーム画面に追加が必要）で、ボタンは状態に合うものだけ（［この端末で受け取る］か［テスト通知］［この端末では受け取らない］）。
- **一度だけ見せる秘密（パスワード）：** アクセント色の枠に等幅で大きく出し、［コピー］と「この画面でしか見られません」を添える。
- **ユーザー管理：** シートで開く（設定の上に重ねるので、ページの最上位に描く）。追加、ユーザーの一覧（記録の件数・研究・作成・最後のログイン）、再発行と停止（押すと確認の文言に変わる）、研究用CSV。
- **予測を必ず出す：** 記録の画面には、データからの予測を7段階それぞれの確率の棒で出す（最も確率の高い段階を塗り、本人の答えを枠で示す）。あわせて、その瞬間のちょうどよい温度・範囲と、その場の温度が中心から何℃か（範囲の中か、外ならどれだけ外か）を書く。感じ方を選んでから見せる（先に見せると答えが予測に引っ張られ、学習の元になるずれが歪むため）。予測は**送信した時刻**の観測値・選んだ場所と風で計算し直し、画面を開いた時刻と送信時刻の両方とともに記録に残す。成績（当たり・対数損失・偏り・平均のずれ・直近10件）は設定と根拠の画面に集計する。
- 記録は天気の保存とは別の場所に置き、［保存データを消去］では消えない。設定の「最近との差 β」で件数を見て、CSV に書き出し、消せる（消すときは2回押す）。

- **計算の根拠（研究用 β の約束）：** β の値には必ず根拠の画面を付ける。「最近との差 β」の［根拠］と、設定の α の下の［計算の根拠を見る］から開く。対象日・比較日を切り替えて、次を並べる。
  - 最近の基準：式、α（半減期・前日の重み）、過去の日ごとの日平均・重み・出どころ（確定／暫定／予報／欠け／取得中）、そろっている重みの割合
  - 気温の差：その日の平均気温 − 基準 の引き算と、平均気温の出どころ
  - 日なた・日かげの差：日中・昼・夕方の気温・湿度・風（観測→人の高さ）・日射と、その時間帯の日なた温度・日かげ温度、使った式と設定値
  - この日のちょうどよい温度・範囲（95%区間）と入力、日なた／日かげが中心から何℃か
  - モデルの式と、各要素の初め（固定の事前分布。肌感の表示の境目からは作らない）・今の値・95%区間。要因は区間が 0 をまたげば「まだ分からない」、またがなければ「効いている」
  - α（標準値か、記録から選んだか）と、予測の成績
  - 合計の値は要約と同じ関数で出すので、根拠の画面と要約の数字は必ず一致する

## 4.11 動いている間

- ドラムが動いている間（指が触れている間と、止まるまでの短い間）は、表示する日の並びを変えるスイッチ（連動／個別、比較のしかた）を押せないようにして、薄く表示する。止まればすぐに押せる。
- それでも動いている途中で日の並びが変わったときは、その操作を取りやめて、選んでいる日に戻す（違う日に止まらない）。
- 比較のしかたの表示は、いつも今の組み合わせと一致させる。個別で日を動かして組み合わせがプリセットから外れたら「カスタム」に、プリセットと一致したらその名前にする。連動に戻すときも、プリセットと一致していればその名前のままにする（前日なら前日）。

## 5. 閉じ方・戻り方

**オーバーレイのシート（肌感マップ・似た日・カレンダー・設定）はすべて同じ閉じ方にする。**

1. 上端のグラバー（つまみ）を下へドラッグ（速く弾いても閉じる）
2. 見出しの右端の ×
3. 背景（暗くなった部分）をタップ
4. Esc キー

- 下部の「閉じる」ボタンは置かない。
- 選ぶシート（似た日・カレンダー）は、選んだら閉じる。
- 「‹ 日別」は**シートの中で前の画面に戻る**ためのもの。閉じるのには使わない。
- グラフのシートは閉じない。高さを変えるだけ（最小／中／最大）。最大まで上げたときは項目チップの下で止まる。
- **高さ：** 画面として見るオーバーレイ（肌感マップ・似た日・設定）は、グラフのシートを最大まで上げたときと同じ高さで開く（`size="full"`）。カレンダーのような短い選択は、中身の高さで開く（`size="fit"`）。

## 7. 動き（`MOTION`）

| トークン | 時間 | 用途 |
| --- | --- | --- |
| `quick` | 140ms | 押したときの反応（縮む、色が変わる） |
| `base` | 220ms | 切り替え、帯の移動、ピンの出入り |
| `enter` / `exit` | 380 / 260ms | オーバーレイの開閉（閉じる方を短く） |
| `settleMin–Max` | 220–460ms | 指を離した後にシートが止まるまで（距離と速度で決める） |

- イージング：`standard` は一般の動き、`sheet`（iOS のシートに近い減速）はシート、`exit` は閉じるとき。
- シートの物理：速度は直近 100ms から測る。弾く速さが 0.4px/ms を超えたら、少なくとも1段は動かす。端では輪ゴムのように抵抗をかけ、指を離すと戻す。
- グラバーは指が触れている間、幅を広げて明るくし、触れていることを伝える。
- `prefers-reduced-motion` のときはアニメーションを止める。

## 8. 効果

- 背景を暗くする：グラフシート `effect.scrim`＋ぼかし 2px、オーバーレイ `effect.backdrop`＋ぼかし 4px。
- 浮いたものの影：カード `shadow.card` → シート `shadow.sheet` → オーバーレイ `shadow.overlay`。固定表示の行は `shadow.pinned` と `effect.blur` で、すりガラスのように見せる。
- 面の上端にだけ、ごく薄く明るいグラデーションを入れる（光が上から当たっているように見せる）。
- 中央の帯：連動中は実線＋にじみ、個別のときは破線でにじみなし。
