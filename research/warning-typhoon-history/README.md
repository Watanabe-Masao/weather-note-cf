## 1. 警報・注意報（高知地方気象台の PDF）

### 確かめたこと
- **載る時期**：月の PDF の `last-modified` は、2025-01 → 2/25、2025-06 → 7/22、2025-12 → 1/22、2026-05 → 6/22、2026-06 → 7/21、2026-07 → 8/24、2026-08 → 9/17、**2026-09 → 10/23**。翌月の **17〜27日** に載る。2025-03・04 は 5/16 にまとめて載った。
- **2026-10・11**：2026-11-18 10:17 JST の時点で **どちらも 404（まだ載っていない）**。10月分は 11月下旬に載ると思われる（推測）。
- **新しい様式（2026-06〜）**：
  - 1行 ＝「発表日時（分まで）× 種類」。種類は「レベル２大雨注意報」「レベル３大雨警報」「レベル４大雨危険警報」「レベル２土砂災害注意報」「波浪警報」など新しい名前。
  - 列は高知県の 34 市町村（高知市が先頭）。
  - 印：●発表、○継続、解 解除、▼警報から注意報、■特別警報からの切替、◆危険警報からの切替（凡例）。
  - 古い様式にあった「斜体字が発表」は無くなり、**発表は ● という別の印**になった（WN-03 で読めなかった問題は新しい様式では起きない）。
  - 1か月の発表の回数（発表日時の数）：6月 73、7月 50、8月 40、9月 53（WN-03 の数え方と同じ結果）。
  - 警報の行は2行に折り返して描かれ、同じ発表日時の下に「レベル３大雨警報」と「レベル２大雨注意報」が並ぶ。
- **ある発表日時に載る種類**：9/4 16:28 の行は雷注意報（○継続）だけで、そのとき続いていた波浪注意報の行は無い。#267 で見た「Ｒ０６の電文は変わった要素の分だけ出る」と同じ形で、**PDF の行は Ｒ０６ の要素ごとの電文（VPWW55〜61）に対応している**と思われる（推測。照らし合わせて確かめる必要がある）。
- **読み取りの正確さ**：
  - `pdftotext -layout` の文字では、行（発表日時・種類）と印の並びは正しく取れた（9月の先頭 25行を、ページの画像と見比べた）。
  - 位置から市町村の列を決める読み方（WH-01 の2回目）は、列の名前の下の「市・町・村」の行から **34列中28列** しか取れなかった（2行に分かれた名前の列が抜ける）。警報の行の折り返しでは、時刻が次の行にずれた。**直せば読める見込みだが、今の読み方のままでは使えない**。

### 照らし合わせの鍵（案）
| PDF | 保存している電文 |
|---|---|
| 発表日時（日本時間、分まで） | `Head/ReportDateTime`（分まで） |
| 種類（「レベル２大雨注意報」など） | `Kind/Name` |
| 市町村の列（34） | `Area/Code`（市町村等、高知市 3920100） |
| 印（●○解▼■◆） | `Kind/Status`（発表・継続・解除）、切替は前の種類（`LastKind`）と組み合わせ |

- 「来るはずの電文」は、PDF の「発表日時 × 種類」ごとに1通（Ｒ０６）と考えるのがよいと思われる（推測）。VPWW53 は発表日時ごとに1通。
- 欠けが見つかっても、電文のファイル名は秒まで（`Control/DateTime`）なので、PDF の分までの時刻からは名前を作れない。**PDF は「欠けを見つけて記録する」ためのもので、取り戻すためのものではない**（一覧から外れた後も電文は少なくとも約2時間は読めた、#267）。

### 2026-11-10 以降の保存分との照らし合わせ
- **まだできない**。11月分の PDF は12月下旬に載ると思われる（推測）。10月分は、本番に保存が無い期間（警報の保存は 2026-11-17 に始まった、`warningArchive.ts`）。
- 11月分が載ったら、本番の数（`/api/health` の `state.warnings.telegrams` と種類ごとの `latest`）と、保存した電文の「発表日時 × 種類」を PDF と照らして、一致・食い違いを数える。
- research/warnings/samples の 14通は 11/10〜11/17 の分で、11月の PDF が載ったら同じように照らせる。

## 2. 台風情報

### 確かめたこと
- **防災情報のページ**（`/bosai/typhoon/data/targetTc.json`）：今ある台風だけ。11/18 は空（`[]`、最後の更新 11/12）。履歴は持たない。
- **台風位置表**：2001年からの台風の中心位置・中心気圧・最大風速などを「時刻ごとに」掲載（PDF・CSV）。2026 年の確定値は台風ごとに追加される（第14〜17号を 11/16、第9〜13号を 10/28 に掲載）。修正の履歴（CSV）もある。
- **ベストトラック**（RSMC Tokyo、`Besttracks/bst2026.txt`、56,826 バイト、最後の更新 11/16）：2026 年は 17個。最後の第17号（NANGKA）は 52件、**すべて6時間おき**の位置。
- **台風経路図**：1951年からの年ごとの図。

### 分からなかったこと
- 台風位置表の CSV の置き場所と時刻の間隔：`table2026.html` は過去の台風資料の案内のページで、CSV へのリンクは出なかった（JavaScript で出ていると思われる。推測）。確かめられなかった。
- 発表1回ずつ（3時間ごと・接近時は1時間ごとの台風情報）の記録が、配信一覧のほかにあるか：**見つからなかった**（「無い」とは言い切れない）。

### 照らし合わせの鍵（案）
- 台風番号 × 解析時刻（ベストトラック・位置表）↔ 台風の電文の `Head/TargetDateTime`（解析の時刻）と台風番号。
- ただし記録は6時間ごと（ベストトラック）で、確定するまで数週間〜数か月かかる。**「6時間ごとの解析の電文が1通も無い時間帯」は見つけられるが、3時間ごと・1時間ごとの発表の抜けは見つけられない**。

| 出どころ | 読む間隔（案） | 読む量 | 規約・robots.txt |

| 警報の PDF | 毎日1回、前の月の PDF があるか HEAD で見る（翌月 17日〜）。載ったら1回だけ読む | 1か月 120〜380KB を1回 | 利用規約に沿う（出典）。robots.txt 404 |
| ベストトラック（bst2026.txt） | 週1回 | 約57KB | 同上 |
| 台風位置表 | 置き場所が分からないので未定 | — | 同上 |

- どちらも量は小さく、自動で回せる。
- PDF の読み取りは、列の割り当ての直し（2行の名前の列、警報の行の折り返し）が要る。
- 照らし合わせの結果は「取り戻せない欠け」として記録する用途（#299 の P2「定期的な整合性の監査」に近い）。
