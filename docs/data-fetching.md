# 取ってきたデータの取り置き（TanStack Query を使う範囲）

2026-11-25 渡辺さん：「状態管理が複雑になってきているのであればライブラリの検討も」「使用用途と範囲は明文化させた上で範囲を限って使用」「範囲に限って入れてないかのテストは必要」。
見本（#514）で比べた結果、**短い間だけ使うデータ**の取り置きに限って TanStack Query（`@tanstack/react-query`、MIT）を使う。

## 使う用途

画面を開いている間だけ要り、少しすると古くなるデータの取り置きに使う。決まりはどれも同じ：

- 古くなるまでの時間（`staleTime`）を、そのデータの決まりで書く（今日と先の日は10分＝`LIVE_EVERY` など）
- アプリに戻ったとき・つながり直したときに、古ければ取り直す
- 取り直している間も、失敗しても、最後に取れた分を出したまま（いつ取れた分か・失敗したかを画面に渡す）

## 使わない所

- **比較の表の日別・時別（`src/data/store.ts`・`db.ts`・`queue.ts`・`plan.ts`）**：確定した日をずっと持つ・訂正の版・月ごとにまとめて取る・優先の順・日ごとにブラウザへ保存、を作り込んでいる。TanStack Query のブラウザへの保存は取り置き全体を1つにまとめるので、何年分もの時別には合わない。自前のまま。画面に返す状態の形（読み込み中・失敗・取れた時刻）だけそろえる。
- **Worker（`worker/`）と共有（`shared/`）**：画面の外なので使わない。
- **画面の状態（どの日・どのタブ、`src/state.ts`）**：取ってきたデータではないので使わない。

## 使ってよいファイル

下の表にあるファイルだけが `@tanstack/react-query` を読み込んでよい（`test/data/query-scope.test.ts` が、表と実際の読み込みを比べる。表に無いファイルで使う・表にあるのに使っていない、のどちらでも落ちる）。置き換えたら、ここに足す。

| ファイル | 用途 |
| --- | --- |
| `src/main.tsx` | アプリ全体に取り置きを渡す（`QueryClientProvider`） |
| `src/data/queryClient.ts` | 取り置きの共通の決まり（戻ったとき・つながり直したときの取り直し、失敗の取り直し1回、見ていない取り置きは30分で手放す） |
| `src/data/historyCache.ts` | 予報の移り変わり（`/api/forecast-history`） |

## 置き換える順（予定）

予報の移り変わり（済）→ 空気（`src/data/air.ts`）→ 台風（`src/data/typhoon*.ts`）→ 雨雲（`src/ui/rainNow/rainNowData.ts`）→ 公式の予報（`src/data/official.ts`）。1つずつ PR にして、テストと e2e で確かめる。
