## 1. 月の色（高さで変わる赤・黄・白）

### 仕組み（式）
月の光 S(λ) ＝ 太陽の光 × 月の反射の割合 × 大気の透過。

1. **太陽の光**：温度 5772K の黒体で近似（吸収線は入れない）。
2. **月の反射の割合**：波長にほぼ比例して増える（月はわずかに赤い）。`1 + k(λ − 550nm)/550nm`。k は「月の B−V が太陽より 0.25 等赤い」に合わせて決めた（k ＝ 1.14、400nm で 0.69、700nm で 1.31）。
3. **大気の透過**：`exp(−m(h) × (τR(λ) + τO3(λ) + τA(λ)))`
   - m(h)：大気を通る道のりの長さ（Kasten & Young 1989）。`m = 1 / (sin h + 0.50572 (h + 6.07995)^−1.6364)`、h は見かけの高さ（°）。地平線で約38。`shared/sunLoad.ts` と同じ式。
   - τR：空気の分子による散乱（Bodhaine ほか 1999 の式30、海面 1013.25hPa）。`τR = 0.0021520 (1.0455996 − 341.29061 λ^−2 − 0.90230850 λ^2) / (1 + 0.0027059889 λ^−2 − 85.968563 λ^2)`（λ は µm）。
   - τO3：オゾンの吸収（Chappuis 帯）。断面積 × 300 DU（8.06×10^18 分子/cm²）。
   - τA：ちり（Ångström の式 `β λ^−α`）。晴れた日の典型 β ＝ 0.05、α ＝ 1.3（β を 0.10 にした表も出す）。
4. **色への変換**：CIE 1931 の等色関数（Wyman・Sloan・Shirley 2013 の近似式）で XYZ → Bradford の色順応で「白の基準」を D65 にそろえる → sRGB（IEC 61966-2-1 の行列とガンマ）。
5. **白の基準と明るさ**：
   - 白の基準は2通り出した。**A：天頂の月の光を白に**（夜、月の光に慣れた目。高い月が白に見える）。**B：大気の外の太陽の光を白に**（昼の目。高い月でもクリーム色）。
   - 明るさは色と分けた：sRGB はいちばん強い成分を 255 にそろえ（色合いだけ）、明るさの比は別の列に出した（大気の外の月 ＝ 1）。

### 仕組みが分かったこと／値が確かめられたこと
- 仕組み：上の式で、赤（0〜2°）→ 橙（5°）→ 黄（10°）→ 白（30°〜）の流れが出る。β が大きい（霞む）ほど低い月が赤く暗くなる。
- 値が確かめられたもの：
  - Kasten–Young の係数（0.50572・6.07995・1.6364）は複数の実装と一致（pvlib、NASA OceanColor）。
  - Wyman ほかの等色関数の係数は、論文の式を引いた実装と一致（z の 1.217・0.681・0.0385・0.0725 など）。
  - オゾンの山（603nm、5.23×10⁻²¹ cm²）。
- **値をまだ確かめていないもの**：
  - 計算した色そのものを、実際の月の写真・測色と比べていない（比べる資料が見つからなかった）。
  - オゾンの断面積は、山（603nm）の値のほかは測定の表から写したものではない近似の値。Serdyuchenko・Gorshelev の表で置き換えるとよい。
  - 太陽の光を黒体にしたこと、水蒸気・酸素の吸収を入れていないこと、観測地を海面にしたこと。
  - 月の赤さ（B−V で 0.25 等）は、B・V の通り道を中心 445・551nm のガウスで近似して合わせた。

## 2. 月の傾き（光っている側が空のどちらを向くか）

### 仕組み（式）
**A（Meeus の式）**：光っている縁の位置角 χ（48章、北から東回り）と、パララクティック角 q（14章、北から天頂の方向までの角）の差 `χ − q` が、「天頂の方向から反時計回り（空を見上げて左回り）に測った、光っている縁の向き」。

- `tan χ = cos δ☉ sin(α☉ − α) / (sin δ☉ cos δ − cos δ☉ sin δ cos(α☉ − α))`（☉ は太陽、α・δ は月の赤経・赤緯）
- `tan q = sin H / (tan φ cos δ − sin δ cos H)`（H は月の地方時角、φ は緯度）

**B（地平の座標で直接）**：Astronomy Engine で月と太陽の高さ・方位（観測地から、大気差あり）を出し、東・北・上のベクトルにする。月の方向に垂直な面に「天頂」と「太陽の方向」を写し、その2つの角を測る。画面の上（天頂の方向）から反時計回りの角になる。

- Astronomy Engine で使う関数：`Equator(Body.Moon/Sun, t, observer, true, true)`（観測地から、その日の座標、光行差あり）→ `Horizon(t, observer, ra, dec, "normal")`（大気差あり）。A の地心の座標は `GeoVector` → `Rotation_EQJ_EQD` → `EquatorFromVector`、恒星時は `SiderealTime`。
- 形（欠け方）は今の `moonPhase` の `Illumination(...).phase_fraction` と組み合わせる。海（模様）の向きまで描くなら `RotationAxis(Body.Moon, t)`（月の自転軸の向き）がある（今回は確かめていない）。

## 3. 端末の傾き（横向き・斜めに持ったとき）

### 仕組み（W3C の仕様）
- alpha・beta・gamma は **Z − X' − Y'' の内因的なテイト・ブライアン角**。回転行列は `R = Rz(α)·Rx(β)·Ry(γ)`（列が、端末の x・y・z 軸が地面の座標〔東・北・上〕でどこを向くか）。beta の範囲は −180〜180。
- Chrome（50 から）は `deviceorientation` の値を地球の座標の絶対値にしなくなり、絶対値（北が基準）は **`deviceorientationabsolute`**。iPhone の Safari には `deviceorientationabsolute` が無い。
- iPhone の Safari は **`webkitCompassHeading`**（磁北からの方位、時計回り）を出す。alpha は北が基準ではない。

### 式（`orientation.mjs`）
1. 行列 R を alpha・beta・gamma から作る（上の式）。**角のまま計算しない**。
2. 背面カメラの向き `f = R·(0, 0, −1)` → 高さ `asin(f_z)`、方位 `atan2(f_x, f_y)`（北 0・東 90）。
3. 画面の向き θ（`screen.orientation.angle`）で、画面の中身の上を端末の軸から選ぶ：`上 = cos θ·y + sin θ·x`（θ ＝ 90 は反時計回りに回した横向き）。
4. 画面の回り（ロール）：月の方向に垂直な面で、「天頂の方向」と「画面の上（R で地面の座標にしたもの）」の角。空の絵をこの角だけ逆に回す。
5. 真上・真下（高さが ±89.9° を超える）では、方位とロールは決まらない → 直前の値を保つ。

持ち方ごとの値（R から戻した alpha・beta・gamma と、出した方位・高さ・ロール）：

| 持ち方 | angle | alpha, beta, gamma | 方位 | 高さ | ロール |
|---|---|---|---|---|---|
| 縦・北・水平 | 0 | 0, 90, 0 | 0.0 | 0.0 | 0.0 |
| 横（左回し）・北・水平 | 90 | 90, 0, −90 | 0.0 | 0.0 | 0.0 |
| 横（右回し）・北・水平 | 270 | 270, 0, 90 | 0.0 | 0.0 | 0.0 |
| 横（左回し）・東・30°見上げ | 90 | 180, −180, 60 | 90.0 | 30.0 | 0.0 |
| 縦・北・右へ10°傾け | 0 | 270, 80, 90 | 0.0 | 0.0 | 10.0 |
| 縦・北・89.5°見上げ | 0 | 0, 179.5, 0 | 0.0 | 89.5 | 0.0 |
| 縦・北・89.95°見上げ | 0 | 0, 179.9, 0 | — | 89.9 | — |

- 横向きでは、同じ「北を水平に見る」姿勢でも alpha・gamma が縦向きと全く違う値になる。**今の `lookFrom` は縦向きだけが前提**なので、横向きでは方位がずれる（推測。実機では確かめていない）。
- **beta 90°の近く（縦に立てた姿勢）**では、alpha と gamma が入れ替わる（(30, 89.99, 0) と (60, 89.99, −30) はほぼ同じ姿勢で、行列の差は 0.0001）。角のまま平滑化すると跳ぶが、行列から出した方位はどちらも 330.00° で続く。→ **平滑化は角ではなく、行列（か向きのベクトル）で行う**。

### 確かめられなかったこと（実機が要る）
- `webkitCompassHeading` が横向き・斜めでどの軸の方位を出すか。AR.js では「iPhone を横にすると物が 90°ずれる（Android では起きない）」という報告と、その直し（端末の回りに合わせてカメラを回す）がある。仕様の文書は見つからなかった。
- `screen.orientation.angle` の向き：iOS 16.4 で、Android と逆の値を返すという報告（WebKit bug 254863、「RESOLVED INVALID」）。今の iOS でどちらかは確かめていない。
- iPhone で alpha（北が基準でない）と `webkitCompassHeading` をどう組み合わせると、横向き・見上げでも正しい方位になるか。案：行列で出した「端末の上の方位」と `webkitCompassHeading` の差を、端末を立てているときに測ってずれ（オフセット）として持ち、行列の方位に足す（推測、実機で確かめる）。

出どころ：
- W3C Device Orientation and Motion（Z−X'−Y''、beta の範囲）：https://www.w3.org/TR/2024/WD-orientation-event-20240509/
- 同（縦に立てたときの beta 90）：https://w3c.github.io/deviceorientation/
- Chrome 50 の変更（deviceorientationabsolute）：https://developer.chrome.com/blog/device-orientation-changes?hl=en
- MDN（deviceorientationabsolute の対応状況、iPhone の Safari は無し）：https://docs.w3cub.com/dom/window/deviceorientationabsolute_event
- iPhone の Safari の alpha と webkitCompassHeading：https://www.w3cschool.cn/doc_browser_support_tables/browser_support_tables-deviceorientation.html
- AR.js の報告（iPhone の横向き）：https://www.github.com/AR-js-org/AR.js/pull/165
- WebKit bug 254863（iOS 16.4 の screen.orientation.angle）：https://bugs.webkit.org/show_bug.cgi?id=254863

## 4. 見かけの大きさ（地心と観測地）

### 仕組み
- 観測地は地球の中心より月に近いので、月が高いほど少し大きく見える。
- 式（近似）：`観測地からの直径 ≈ 地心からの直径 × (1 + sin h × sin π)`、π は月の地平視差（約 0.95°、sin π ≈ 6378km ÷ 地心距離）。
- Astronomy Engine なら近似は要らない：`Equator(Body.Moon, t, observer, true, true).dist`（観測地からの距離、AU）で `2 asin(1737.4km ÷ 距離)`。今の `moonDistance` は地心の距離（`GeoMoon`）。

### 値（`moon_tilt.cjs`、高知、2026-11-24〜25）
| 日時（JST） | 月の高さ | 地心の距離 | 観測地からの距離 | 地心の直径 | 観測地からの直径 | 比 |
|---|---|---|---|---|---|---|
| 11/24 18時 | 17.7° | 361,359km | 359,383km | 33.06′ | 33.24′ | 1.0055 |
| 11/24 21時 | 53.6° | 361,038km | 355,891km | 33.09′ | 33.57′ | 1.0145 |
| 11/24 23時 | 76.9° | 360,839km | 354,629km | 33.10′ | 33.68′ | 1.0175 |
| 11/25 4時 | 37.0° | 360,395km | 356,526km | 33.15′ | 33.51′ | 1.0109 |

- 近似の式で 76.9° のとき 1 + sin 76.9° × (6378 ÷ 360839) ＝ 1.0172 で、Astronomy Engine の 1.0175 とほぼ合う（仕組みの確かめ）。
- 違いは最大で約1.8%（約0.6′）。画面の月の大きさとしては目に見えないほど小さい。

## おすすめ（まとめ）
- 色：**白の基準 A（天頂の月を白に）、β ＝ 0.05 の表**を、高さで補間して使う（月の光に慣れた目に近い）。明るさは色と分け、別の段で扱う（空の色のモデルと同じ考え）。
- 傾き：**B（地平の座標で、観測地から見た太陽の方向を写す）**。
- 端末：**行列で計算し、平滑化も行列か向きのベクトルで**。画面の向きは `screen.orientation.angle` で選び直す。iPhone の方位の扱いは実機で確かめてから。
- 大きさ：観測地からの距離で出す（違いは小さいので、後でもよい）。

# MA-02：月の見え方（明るさと背景）

昼の低い月が夜と同じ赤いオレンジになる（11/20 渡辺さんの実機）ことを直すため、「その時の空の明るさの中で、人の目にどう見えるか」を、**物理の量 → 背景との比 → 見え方** の順で計算できる形にした。

- 調べた日：2026-11-20。画面のコードは触っていない。
- 外部のページは開かず、検索の結果（要約）だけで出どころを確かめた。
- 計算：`ma02_positions.cjs`（代表例の太陽・月の位置、Astronomy Engine）→ `ma02_visibility.py`（輝度・背景・見え方。MA-01 の `moon_color.py` を使う）。
  - `NODE_PATH=<astronomy-engine の node_modules> node ma02_positions.cjs > /tmp/ma02_pos.json`
  - `python3 ma02_visibility.py /tmp/ma02_pos.json`
- **値の多くは文献の典型値と推測の組み合わせで、実際の空で測って確かめたものではない。** 下の各項で「出どころのある値」と「推測」を分ける。

## 1. 月の表面の輝度（cd/m²）

### 式
- 月全体の V 等級（Krisciunas & Schaefer 1991 の位相の式）：`m = −12.73 + 0.026|α| + 4×10⁻⁹ α⁴`（α は位相角、°）。距離で `+5 log10(d / 384400km)`。位相角が 7° より小さいと、衝効果でこの式からずれる。
- 大気の外での照度：`E = 2.54×10⁻⁶ × 10^(−0.4 m)` lx（0 等星の照度。**推測**：よく使われる換算で、出どころは確かめていない）。満月で 0.31 lx（満月の夜の照度 0.05〜0.3 lx、月光 約 0.2 lx という値と合う）。
- 光っている部分の平均の輝度：`L₀ = E / (Ω × k)`、Ω ＝ π (1737.4km / d)²（月の円の立体角）、k ＝ 輝面比。
- 大気を通ったあと：`L = L₀ × T(h)`。T は MA-01 の大気（Kasten–Young の道のり、分子の散乱、オゾン、ちり β）を目の感度で重み付けしたもの。

### 値（距離 38.44 万km）
| 位相角 | 輝面比 | 月全体の等級 | 照度（大気の外） | 光っている部分の輝度（大気の外） |
|---|---|---|---|---|
| 0°（満月） | 1.00 | −12.73 | 0.31 lx | 約 4,900 cd/m² |
| 57° | 0.77 | −11.21 | 0.077 lx | 約 1,560 cd/m² |
| 90°（半月） | 0.50 | −10.13 | 0.029 lx | 約 890 cd/m² |
| 120° | 0.25 | −8.78 | 0.0083 lx | 約 520 cd/m² |

- 欠けるほど、光っている部分そのものも暗くなる（明暗の境の近くは斜めに光が当たるため）。
- 大気を通ったあとの割合（β 0.05）：高さ 60° で 0.78、30° で 0.64、12° で 0.35、0.3° で 0.0009（MA-01 の表と同じ）。

## 2. 空の背景の輝度（cd/m²）

### 式（月のある方向の空の輝度）
- **昼（太陽 0° 以上）**：CIE 標準一般天空（ISO 15469 / CIE S 011）の相対分布 `L/Lz = f(χ)·φ(Z) / (f(Zs)·φ(0))`、`φ(Z) = 1 + a·exp(b / cos Z)`、`f(χ) = 1 + c·(exp(dχ) − exp(dπ/2)) + e·cos²χ`。晴れは型12（a −1、b −0.32、c 10、d −3、e 0.45）、曇りは型1。χ は空の点と太陽の離角なので、**離角が小さいほど背景は明るい**。
  - 絶対値（cd/m²）は、空からの水平面照度に合わせて決めた：`E_d = 400 + 15000 × sin(h☉)^0.6` lx（**推測の式**：日の出入りの約 400 lx と、直射日光を除いた昼の 1〜2.5 万 lx に合わせた）。
- **薄明（太陽 0〜−18°）**：水平面照度を対数で補間（0°：400 lx、−6°：3.4 lx、−12°：0.008 lx、−18°：0.0006 lx）し、空を一様と見て `L = E/π`（一様とみなすのは**推測**）。
- **夜**：街の明かりの空（高知市を 18.5 等/平方秒角と**仮定**、約 0.0043 cd/m²）＋ 月の光が空に散った分（満月の夜の空 約 18 等/平方秒角を、位相の式で弱める）。等/平方秒角から cd/m² は `10.8×10⁴ × 10^(−0.4 m)`（**推測**：よく使われる換算）。
- **曇り**：厚い雲では月は見えない（月の光を 0 にする）。薄曇りは雲の透過が分からないので入れていない。

### 何桁変わるか（この式で）
| 場面 | 背景の輝度 |
|---|---|
| 昼、月が地平線の近く（太陽 29°、離角 122°） | 約 4,200 cd/m² |
| 昼、月 30°（太陽 30°、離角 30° → 180°） | 約 6,300 → 2,000 cd/m² |
| 日の入りの直後（太陽 −0.1°） | 約 120 cd/m² |
| 市民薄明の終わりごろ（太陽 −6°） | 約 1.2 cd/m² |
| 航海薄明の終わりごろ（太陽 −12°） | 約 0.009 cd/m² |
| 夜（街の空＋月の散乱） | 約 0.006 cd/m² |

昼から夜まで **約 6 桁**変わる（薄明だけで照度は約 6 桁変わる、という文献と同じ大きさ）。

## 3. 見え方

### 確かめたこと（出どころのある考え方）
- **目の状態**：背景（順応）の輝度で、明所視（約 5 cd/m² 以上、錐体だけ）・薄明視（約 0.005〜5 cd/m²）・暗所視（約 0.005 cd/m² 以下、杆体だけ、色が分からない）（CIE 191:2010）。境の値は資料によって 3 cd/m²・0.001 cd/m² とも書かれる。
- **ハント効果**：同じ色度でも、輝度が高いほど色が鮮やかに見える。CIECAM02・CAM16 では順応の輝度による係数 F_L（三乗根の近似 `F_L ≈ 0.1715 L_A^(1/3)`）でこれを表す。
- **月の円そのもの**は、地平線のすぐ近くを除いて数百〜数千 cd/m² で、夜でも明所視の明るさ（だから夜の低い月の赤は見える）。地平線 0.3° では 約 1.3 cd/m² で薄明視の範囲に落ちる。

### 仕組み（このモデルで、なぜ昼の低い月が赤く見えないか）
- 目に届くのは「大気を通った月の光」＋「月の手前の空の光（空気の光）」の**和**。昼は手前の空の光が月の光と同じか、それより強い（14時の月：月 1.3 cd/m² に対し空 4,200 cd/m²）。足した色は空の青白に寄り、赤みは消える。
- さらに昼の目は明るい空（D65 に近い白）に順応しているので、白の基準も違う。
- 夜は手前の空が 10⁻³〜10⁻² cd/m² しかなく、足しても月の色はほとんど変わらない → 低い月はそのまま赤い。
- → 赤みが目立つのは **背景が月より十分暗いとき（C が大きいとき）だけ**（このモデルの結論。実際の観察で確かめたものではない）。

### 式（アプリで使える形の案）
- コントラスト：`C = L_月（地上） / L_背景`（ウェーバーコントラスト。ここでは「月の光 ÷ 手前の空」）。
- 色の濃さ（0〜1）：`C < 0.02` で 0（見分けの境。ウェーバー比 約 2% は**推測**：よく使われる値）、それより上は `C / (C + 1)`（**推測**の形）。
- 明るさ（背景に対して）：`(1 + C)^(1/3)`（スティーブンスの明るさの指数 約 1/3。**推測**：よく引かれる値で、出どころは確かめていない）。
- 赤み：月の光（MA-01 の色）と手前の空の光（空の色は**推測**：昼 x 0.290・y 0.300、薄明 0.300・0.300、夜の街の空 0.360・0.360）を足した色が、目の白（昼 D65、夜 天頂の月、その間は太陽 0〜−6° で直線につなぐ＝**推測**）から「赤い向き」にどれだけ離れているか（u′v′）。物差しは「夜の目で見た高さ 5° の月」＝ 1。1 を超えたら 1 に切ってよい。

### CIECAM02・CAM16 を使うべきか
- **今は使わなくてよい**と考える（推測を含む）。
  - 入力（順応の輝度・背景・周囲）を決めるのに、上の物理の量（月の輝度・背景の輝度）がどのみち要る。そこまで出せれば、見え方の大部分は「手前の空の光を足す」と「白の基準を昼と夜で替える」で説明できる。

  - 後で確かめるなら、colour-science（Python）の CAM16 で同じ代表例を計算して比べる（新しいライブラリなので、使う前に渡辺さんの OK が要る）。

## 4. アプリで使う形（案）

入力：太陽の高さ・方位、月の高さ・方位、位相角・輝面比・距離、天気（晴れ／曇り）。
1. `L₀`（月の輝度、大気の外）← 位相角・輝面比・距離
2. `T(h)`（大気の透過）← 月の高さ（MA-01 の表を補間）
3. `L_背景` ← 太陽の高さ・離角（昼：CIE 型12 を絶対値に、薄明：照度の表、夜：街＋月の散乱）
4. `C = L₀T / L_背景` → 色の濃さ `C/(C+1)`（C < 0.02 は 0）、明るさ `(1+C)^(1/3)`
5. 赤み ← 月の色（MA-01）＋ 手前の空の色を足した色の、白からの離れ
6. 曇り：月は描かない（または「雲の向こう」の印だけ）

画面での使い方の案：
- 月の円の不透明度 ＝ 色の濃さ。
- 月の色 ＝ 白と MA-01 の色（その高さ・夜の目）の間を、赤みで混ぜる（赤み 1 で MA-01 の色）。
- 明るさは、背景の空の絵に対する明るさ（光の輪など）に使う。

## 5. 確かめられなかったこと・推測のまとめ
- 昼の空からの水平面照度の式（`400 + 15000 sin^0.6`）、薄明の空を一様とみなすこと、高知市の夜空の明るさ（18.5 等/平方秒角）、空の色度、色の濃さの式の形、ウェーバー比 2%、スティーブンスの指数 1/3、0 等星の照度の換算：**どれも推測か、出どころを確かめていない値**。
- 薄曇り（雲の透過）は分からず、入れていない。
- 計算した見え方を、実際の空（写真・目視）と比べていない。渡辺さんの実機の画面と、実際の空を見比べてもらうのがいちばん確か。
