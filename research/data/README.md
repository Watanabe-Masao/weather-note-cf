# 研究用の分析データ（DuckDB）

> ふだんの分析は iPhone のアプリの中で完結します（［設定 › ユーザー管理 › 研究用の分析を開く］、`src/research/analysis.ts`）。ここの手順は、パソコンで詳しく分析したいときだけの任意のものです。

研究に協力すると同意した人の記録を、サーバーから読み取り専用で取り出し、DuckDB と Parquet の表にして分析します（#45）。アプリの動きには関係せず、ここの依存（`@duckdb/node-api`、`vite-node`）はアプリには入りません。

## 守ること（再識別を防ぐ決まり、#55）

人数が少ない集まりでは、研究用の番号でも、答えた時刻の並びや答え方から本人が分かることがあります。そこで次を決まりとします。

1. **行ごとのデータは、管理者の手元のパソコンから出さない**：`raw/`・`parquet/`・`csv/`・`*.duckdb` が対象です。人との共有、チャットや AI への貼り付け、スクリーンショットも「出す」に含みます。リポジトリにも入れません（`.gitignore` 済み）。
2. **外に出すのは集計だけ。1つの集計に5人以上いるときに限る**：記録の件数ではなく人数で数えます。満たさない集計は出しません（`npm run check` の最後に、データセットごとの人数と、この条件を満たすかを出します）。
3. **個人ごとの推定（ちょうどよい温度 μ・範囲 h など）は、本人にだけ見せる**：アプリの中で本人が見るものです。研究の結果として個人の値を出しません。

取り出しの仕組みも、これに合わせています。

- **取り出しは専用のトークンで**：管理画面で作る「取り出し用のトークン」だけで取り出せます（読み取り専用・24時間で失効・作り直すと前のものは無効・いつでも無効にできる・サーバーにはハッシュだけ）。管理者のログインでは取り出せません。取り出すたびに、誰が・いつ・何件をサーバーに記録します（管理画面の「読み出しの記録」）。
- **アカウントとのつながりを持たない**：名前・ログインID・アカウントの ID（記録の `owner`）は出てきません。人は `research_id` で区別します。
- **撤回と削除はすべての写しに届く**：取り出すたびに、`raw/` にある過去の写しを、最新の取り出しに合わせて削ります。同意を取り消した人、アカウントを削除した人、削除された記録は、すべての写しから消えます（`purged` に番号、`trimmed` に件数だけ残ります）。
- **同意し直すと別の番号**：同意を取り消すと研究用の番号が新しくなります。同意し直したあとの記録は新しい番号で入り、取り消す前の記録と古い番号は戻りません（記録の ID で2つの番号が結びつくのを防ぐ）。
- **共有は差し引きにも注意**：5人未満のセルに加え、差し引きでそれが分かってしまうセルも共有に入りません。日を変えて何度も共有すると、その差から新しく加わった人が分かることがあるので、共有は必要なときだけにします。
- **取り出しが大きく減ったら止まる**：前回の半分より少ないと、過去の写しを削らずに止まります（取り出し先の間違いで写しが消えないように）。
- **管理画面から研究用の CSV は落とせない**：ダウンロードした写しは消しようがないためです。Excel で見たいときは、手元で `npm run csv` を使います（`raw/` から作るので、撤回が届きます）。

## 使い方

```sh
cd research/data
npm install
WN_URL=https://weather-note-cf.<…>.workers.dev WN_TOKEN=<取り出し用のトークン> npm run export   # raw/ds-<日時>.json
npm run build        # raw/ → weather-note.duckdb と parquet/
npm run run-models   # 人ごとにモデルを計算 → model_runs・parameter_estimates・evaluation_results
npm run check        # 品質の確認（版の混在、学習から外した理由、確率の合計、重複…）と、外に出せるか
npm run csv          # 最新のデータセットを csv/ に1行1記録で（Excel 用。手元の外に出さない）
```

使い終わったら、管理画面でトークンを「無効にする」を押してください。

本物のデータなしで試すときは `npm run fixture`（作り物の2人・5件を `raw/ds-fixture.json` に書きます）。

## 表

| 表 | 中身 |
| --- | --- |
| `datasets` | 取り出し1回ぶん。日時・表の版・ファイルのハッシュ・件数・人数・消した人数と件数 |
| `sensation_reports` | 答え（-3〜3）と尺度の版、日当たり・風・空、学習に使えるかと外した理由 |
| `weather_snapshots` | 答えたときの気象の値と、どこから来たか（観測・予報）、遅れ、品質の印、変換の版 |
| `prediction_snapshots` | 答える前に保存した予測（7段の確率、中心と幅、区間、分散の内訳、モデルの版） |
| `model_runs` | 計算1回ぶん。コードのコミット・モデルの版・設定 |
| `parameter_estimates` | 人ごと・モデルごとの推定値と区間、重み |
| `evaluation_results` | 人ごとの成績（RPS・スキル・対数損失・当たり・偏り…） |

表の定義と変換の決まりは [transform.ts](transform.ts) にあり、CI のテスト（`test/data/research-transform.test.ts`）で確かめています。DuckDB を使う手順も、作り物のデータで CI が通しで動かします（`.github/workflows/research-data.yml`。research/data・src/beta・src/research・shared が変わったときだけ）。

答えた時点の予測（`prediction_snapshots`）は書き換えません。あとで計算し直した結果は `model_runs` の下に別に入れます（数学的正本 D7）。
