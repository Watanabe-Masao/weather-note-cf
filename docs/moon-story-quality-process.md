# 満月の物語：品質管理の手順書

満月の絵本を、企画から本番まで同じ品質で作るための進め方。何を満たせばよいかは [moon-story-quality-standard.md](moon-story-quality-standard.md)（基準書）、作り方の技術は [moon-story.md](moon-story.md) にある。
この手順書は、コールドムーンの第3次品質改善（PR #524、2026-11-27）で確かめた進め方をまとめたもの。

- シリーズとしてそろえるのは「品質」と「確かめ方」。作品の構成・時間配分・終幕の形はそろえない（作品ごとに決める）。
- 制作の詳しい基準と、測った値・経緯は Project「満月の絵本_制作基準」と、各作品の品質改善の資料にある。
- 新しい作品や品質改善を始めるときは、issue のテンプレート「満月の物語の品質管理」で issue を作り、その中のチェックを順に埋める。

## 0. 役割

| 役割 | すること |
|---|---|
| 渡辺さん | 段階ごとの承認、マージの OK、iPhone 実機確認 |
| メインのスレッド（天気アプリ） | 工程管理・見本と本番の PR・測定・報告。マージは渡辺さんの OK のあと |
| 作品レビュー（外部） | 文学・美術・演出の評価と点数（基準書 12 章） |
| 独立コードレビュー | 作業を見ていない者（別のエージェントなど）がコードを読む。指摘は画面で確かめてから直す |

## 1. 段階と関門

各段階は、前の段階が承認されてから始める。段階ごとに比較の動画を作り、原版を残す。すべてを同時に変えない。

| 段階 | 主に変えるもの | 出すもの | 関門（次へ進む条件） |
|---|---|---|---|
| 1. 企画 | テーマ・主役・9 ページの流れ | 物語企画シート、絵コンテと本文 | 承認B（本文・結末・素材の一覧） |
| 2. 事実と出典 | 自然・文化の描写 | 事実・出典管理シート（事実・伝承・創作を分ける） | 新しい描写ごとに照合済み |
| 3. 素材 | 絵の素材 | 素材の依頼・検収（紺と灰色の上、作品の構図と光で） | 画素の基準（表示の最大×3）を満たす |
| 4. 美術 | 色・光・遠近・素材の配置 | 見本ブランチ、比較の画像 | 作品レビューで承認 |
| 5. 構図 | ページごとの視点・空間の役割 | 見本ブランチ、比較の動画 | 作品レビューで承認 |
| 6. 文章・時間・終幕 | 本文の推敲、文の出し方、秒、終幕 | 新旧対照表、時間の表、比較の動画 | 作品レビューで承認 |
| 7. 見本の最終品質保証 | （変えない） | 測定の結果（基準書の数値）、最終候補の動画 | 作品レビューの最終承認 |
| 8. 本番化 | 採用した案だけを本番へ | 本番の PR（下書き） | 2 章の条件をすべて満たす |
| 9. 完了 | （変えない） | マージ、記録の更新 | 渡辺さんの OK、iPhone 実機確認 |

- 見本は `sample/…` ブランチに置き、URL の切り替えで案を比べる。見本ブランチはマージしない。
- 承認された作品に、重大な問題が無い限り、新たな表現上の改善を続けない。本番化の段階の修正は「確定した表現を正確に再現する」ためのものに限る（そのときは作品全体の再レビューは要らない）。

## 2. 本番化（段階 8）の手順

1. **main との差分を確かめる**：見本を作ったあとに main へ入った修正を一覧にする（`git log <見本の分かれ目>..origin/main -- <移すファイル>`）。見本のファイルを丸ごと移すと、その修正が消える（PR #524 で #523 が消えかけた）。
2. **採用した案だけを移す**：見本の切り替え（URL の `?…`）、不採用の案、見本の印のコメントは入れない。素材は元の PNG を `design-src` に置き、`storyAssets.ts` に登録する。
3. **設計規約に合わせる**：色・透け具合は本の変数（`palette.ts` → `bookVars` の `--bk-*`）、重なり順は層の決まり（`z-index` 0〜3 か `var(--layer-*)`）。単体テストの判定は緩めない（直すのは本番のコード）。`hardcode-budget.json` に足すのは、ほかと同じ性質の値で理由を PR に書けるときだけ。
4. **回帰テストを書く**：承認された演出の順序と時間（基準書 9 章）。設定の値をなぞるだけでなく、場面の動きの記録（gsap のタイムラインの代わりに記録する）で確かめる。例：`test/data/story-direction-cold.test.ts`。
5. **`npm run check`**（型・単体テスト・ビルド）。
6. **画面で確かめる**（3 章の測定）。見本と同じ測り方で、見本と同じ結果になることを確かめる（描画結果の同等性）。
7. **下書きの PR を出す**：PR の本文に、変えたこと・確かめたこと・マージの前に残っていることを書く。報告は PR のコメントで「今回対応／記録して保留／まだ判断できない」。
8. **自然科学・文化の原典照合**（基準書 11 章）。結果で物語の本文を説明的にしない。
9. **独立コードレビュー**：作業を見ていない者に、下の観点で読んでもらう。指摘はすべて画面で確かめ、「確かめた指摘」と「疑い」を分けて直す。演出が変わる直しは、渡辺さんに相談してから。
   - 高：共通の字幕処理（節の消去・再表示・逆方向の移動）、再生の制御（止める・再開・途中のページ）、回帰テストが実際の表示の順を見ているか、ほかの作品への影響。
   - 中：動きを減らす設定・読み上げ・止まった絵、字幕の領域と折り、描く負荷。
   - 低：使われない定義・素材・古いコメント。
10. **CI がすべて成功**（check・pipeline・e2e）。CI が通っていても、描画と時間軸の不具合は残りうる（3 章の測定は省かない）。
11. **iPhone 実機確認**（渡辺さん）。作品レビューのチェックリストに、本番化で直した所を足して見る。
12. **マージ**：渡辺さんの OK のあと、メインのスレッドが squash でマージする。
13. **記録を更新**：Project「満月の絵本_制作基準」と、この手順書・基準書に、今回の教訓を足す（作品ごとの値は【作品】として残し、基準にしない）。

## 3. 測定（画面で確かめる）

`npm run build` のあとに `scripts/story-qa.py` を使う。一本ずつ動かす（並べて動かすと時間が詰まって測られる）。どれも問題があれば終了コード 1。

| 確かめること | コマンド | 合格 |
|---|---|---|
| 字の配置（4 つの画面） | `python3 scripts/story-qa.py layout <満月の日> <幅>`（幅 320・375・390・430） | 取り残しの字・操作ボタンとの重なり・画面の外が 0 件 |
| 再生の可逆性 | `python3 scripts/story-qa.py stops <満月の日>` | 止まる所ごとに、行きと帰りの字・絵の部品・視点が同じ |
| 表示環境 | `python3 scripts/story-qa.py env <満月の日>` | 動きを減らす設定で強制の改行 0、止まった絵に代替テキスト、小さな画面と横向きで字が画面の外に出ない |
| 時間軸（順序と時刻） | `python3 scripts/story-qa.py timeline <満月の日> <絵の部品のセレクタ>…` | 作品の時間の表どおりの順。見本で測った時刻と同じ（描画の間隔の差まで） |
| 通しの見た目 | `python3 scripts/story-capture.py <満月の日> <出力>` | moon-story.md「4. 見直しの仕方」 |
| ほかの作品 | 同じ測定をほかの満月の日でも（共通の処理を変えたとき） | 変わらない |

- 満月の日は UTC の日時（例：コールドムーン `2026-12-23T11:00:00Z`、ビーバームーン `2026-11-24T11:00:00Z`）。
- 字の明るさの比（4.5:1 が目標）は、字が出そろったら止めて撮り、字の後ろの明るさを測る。CSS を書き換えたときは、字の明るさを見本と比べる（PR #524 の 4P は、書き換えで 172 → 119 に暗くなっていた）。
- 結果（数値と画像）は PR のコメントに書き、画像や動画はリポジトリに入れない。

## 4. issue の使い方

- 作品ごと（または品質改善ごと）に、テンプレート「満月の物語の品質管理」で issue を作る。段階の関門・本番化の手順・測定がチェックになっている。
- 本番化の PR からは、その issue を参照する。マージで終わりにせず、iPhone 実機確認と記録の更新が済んだら閉じる。
- 本番化の PR に混ぜない整理（使わなくなった素材の削除など）は、別の issue にして、参照関係を調べた独立した PR で行う。
